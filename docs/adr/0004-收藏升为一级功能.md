# 「收藏」升为一级功能，功能入口不再被登录流程绑定

Status: accepted

Kumone 把「我的歌单 / 收藏的专辑」这些**收藏**从「我的」里拆出来，单独做成一个一级功能（底部导航第四键）；同时取消「未登录就把人踢去登录页」的入口闸门 —— 收藏页与「我的」抽屉**任何时候都能打开**，未登录时给出空态说明与「去登录」按钮，登录完成后原地回到原处。

## 背景

用户报过两件事：①「找不到歌单和收藏在哪」；②「密码登不进」时被迫先登录才能看到自己的东西，于是把「登录」与「进我的内容」焊成了一条流程 —— 点「我的」先跳登录页，登录成功才回来。

代码里还有一个词是混的：网易云的 `/user/playlist` 把**我创建的**和**我收藏的**歌单一起返回（靠 `subscribed` 字段区分），归一化层保留了这个字段，界面却把两者混在同一页、同一行标题里。于是「歌单」这个词同时指两件不同的事。

## 决策

### 1. 「收藏」是一级功能

底部导航从三键变四键：主页 / 广播 / 搜索 / **收藏**。

收藏页只放两件东西：**收藏的歌单**（`subscribed=true`）与**收藏的专辑**。
「我创建的歌单」留在「我的」里 —— 它是云端资产，与账号绑定更紧，和「收藏」不是一回事。

### 2. 入口不被登录态挡住

- 「我的」抽屉：**不再**先查登录态、未登录就跳登录页；未登录时照常打开，各条目写「登录后查看」，只有真的去取数的那一步才需要账号。
- 收藏页：未登录时页面照常打开，两个分区各自给「登录后查看」+「去登录」。
- 登录成功后**原地回来**（沿用既有的登录中断 / resume 机制），不把用户丢回别的页面。

### 3. 三个概念在服务层就分开

`createdPlaylists` / `favoritePlaylists` / `favoriteAlbums` 三个入口各自明确，
原始的 `myPlaylists` 只作为两者的共同数据源，不再直接出现在界面上。

## 考虑过的其他做法

- **入口解耦但不升一级**（收藏仍藏在「我的」抽屉里）：改动最小，但用户仍然要先进「我的」再找一层 —— 用户要的就是「独立」。
- **收藏完全本地化**（收藏列表存本机，不需要网易云账号）：独立性最强，但要另建一套本地数据与同步语义，与网易云账号里的收藏会分叉 —— 用户没要求，且要放弃账号侧的收藏。
- **保持闸门**（未登录仍跳登录页）：实现最省事，但正是用户明确要去掉的耦合。

## 后果

- 底部导航从三键变四键：用户此前报过「一级菜单点错」（当时指的是「资料库」那种大杂烩入口），这次是用**一个明确命名的具体功能**占第四格，不是再塞一个杂物间。
- 快照与语义契约随之变化：模型侧入口名从「我的歌单与收藏」改为「我的」，收藏页是新的视图类型 `favorites`；回归测试与知识包文档同步更新。
- 术语不再重叠：「歌单」在界面上一律带前缀（我创建的 / 收藏的），见 `CONTEXT.md`。

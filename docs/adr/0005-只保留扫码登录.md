# 只保留扫码登录，移除账号密码登录

Status: accepted

Kumone **只有扫码登录这一条路**：账号密码登录整条移除 —— 界面上没有账号/密码输入框，服务层没有 `loginByPassword`，内核门面没有 `cellphoneLogin` / `emailLogin`，登录页也不再需要「账号登录 / 扫码登录」双 Tab。

## 背景

密码登录这条路本来就不稳（2026-11-04 取证，见 `docs/已知问题.md` 第 31 条）：

- 网易云只剩 `/login/cellphone` 一条密码通道，邮箱端点（`/login/email`、`/login/password`）**已 404 下线**；`/login` 虽然活着，但字段名是 `username`（用 `email` 会回 400「参数错误」），而且实测回 `501 登录失败`。
- 密码登录会反复踩风控：服务端对密码错误的计数是**账号级**的，踩到上限会回 `509 密码错误超过限制` —— 一次输错就可能把正确密码也挡住一阵子。
- 无论怎么调编码（明文 / MD5）都改变不了这两条事实。

于是这条路的成本是：用户第一次输错就可能被挡在外面，而且为了登进来，**必须把密码交给本 App**。

## 决策

移除密码登录，只留扫码：

- 登录页只有二维码 + 状态文案（等待扫码 / 已扫码 / 已过期）+「刷新二维码」。
- 已登录时登录页显示「已登录：昵称」+「退出登录」/「切换账号」；换账号 = 退出后重新扫码。
- 与密码相关的配套一并移除：风控码诊断（502/509/503/10004/501）、`redirectUrl` 验证引导（`openUrl` / `copyText` 两个服务层通道）、错误码 `KUMONE_LOGIN_FAILED`。

## 考虑过的其他做法

- **保留密码登录但藏起来**（不在界面露，只在模型/调试通道里）：两边都留 = 两套真相，且风控问题原样存在。
- **保留双 Tab**：为了一个不稳定的备选保留一整个界面分支，Tab 本身也要维护状态。
- **只留邮箱登录**：邮箱端点更不靠谱（`501`），而且扫码对用户更省事。

## 后果

- **登录必须有一台装着网易云音乐 App 的手机**。这是这次取舍的代价：换来的是本 App **永远不接触用户密码**，也不会因为一次输错把人挡在门外。
- 登录页没有 Tab、没有输入框，导航更简单；模型侧的语义契约也少了一类（登录页现在只有二维码与状态）。
- 错误码表少了 `KUMONE_LOGIN_FAILED`（随这条功能一起消失，不留空壳码）。
- 术语表补了「扫码登录」，见仓库根目录 `CONTEXT.md`。

# 设计基线：界面为「人」与「模型」双模态，视觉取 ego 风格

Status: accepted

Kumone 的移动端渲染层同时服务两类消费者：**人**（直接操作 App）与**模型**（读语义快照、驱动 App）。因此界面必须从像素层搬到语义层与 token 层，并额外提供一棵带稳定标识的语义文本树。

视觉不再沿用 Apple Music 观感，改用 **ego 风格**：白底画布、1px 描边、大圆角卡片、克制单色系、少量角色色，粗体主字配细斜体副标。

## 背景

设计理论来源是 [citrolabs/ego-lite](https://github.com/citrolabs/ego-lite) 的界面设计拆解（见 `docs/ego-lite-UI设计理论.md`）。ego-lite 本身**没有一行 UI 代码**（仓库是自动化 harness 与 Skill 包，Chromium 内核闭源），所以可迁移的是它的**设计理论**而非像素。

## 决策

### 1. 界面按消费者分层

人看窗口与状态卡片；模型看语义文本树与错误消息。同一份 DOM 承担两种角色，但**模型侧有独立的读取接口**（`Mobile.snapshot()` / `Mobile.act()`），不要求人去解析像素。

### 2. 界面用语义，不用像素

可交互元素一律用语义标签（`button` / `nav` / `main` / `h1` / `li`）并带 `aria-label`；**无障碍树就是界面契约**。

定位分两个层次，规矩各自不同：

- **模型侧定位**（`Mobile.act()`、知识包 locator 等对外接口）**只接受两种东西**：语义快照里的 ref，或语义定位（role + name）。**CSS 选择器与硬编码坐标不得作为定位参数进入这些接口** —— 它们是实现细节，改个版就废。
- **实现内部操作自己的 DOM 不受此限**：`core/` 与 `views/` 里用 `getElementById` / `querySelector` 拿到自己写的元素是正当做法（例如外壳同步底部导航的选中态）。这条限制的对象是"用样式细节去找语义目标"，不是"程序管理自己的界面"。

这条边界之所以要写清楚：原措辞「禁止裸 CSS 选择器」把两类完全不同的用法混在一起，要么变成无法执行的空话，要么误伤正当代码。

### 3. 观察是只读的

`Mobile.snapshot()` 不得改变任何状态：不动播放、不发请求、不改焦点。它只读 DOM 与状态快照。

### 4. 状态可查询，转移可命名

播放状态由 `player.state()` 查询；转移由 `play` / `pause` / `seek` / `next` / `prev` / `queue` / `setQuality` 等**命名动词**表达，不允许通过直接改 DOM 来"模拟"状态变化。

### 5. 错误按"下一步该干什么"分类

错误分 `transient`（可重试：网络抖动、元素暂未出现）与 `permanent`（须换策略：鉴权失败、目标歧义、引用过期）。等待循环只对 transient 重试。

### 6. 错误码是契约，措辞是实现

错误码表 `KUMONE_*` 是持久契约：**按码分支，不按文案分支**。文案可漂移，码不可改语义。错误消息遵循五要素：期望签名、当前状态、候选、阻塞原因、下一步动作。

### 7. 上下文预算是构建期纪律

界面与文档的体积上限写进构建/自测，超限即失败，而不是评审时口头约定。

### 8. 知识分层披露，长尾改查询

网易云页面的稳定定位器沉淀为知识包（`www/mobile/learnings/`），**只允许稳定 locator，禁止临时 ref**；长尾细节通过查询获取，不写进常驻文档。

### 9. 教学顺序按失败概率排

文档与报错先讲"怎么跑起来、怎么登录"，再讲概念；先教归因，再教动作。

### 10. 约束前移成构建错误

违反约定的写法（模型侧接口接受选择器/坐标、临时 ref、界面层直接改状态）在自测里失败，而不是靠代码评审发现。约束只针对**对外接口的形态**，不对实现内部的 DOM 操作设限（见 §2 的边界）。

## 视觉语言（ego 风格）

| 元素 | 取值 |
| --- | --- |
| 画布 | `#F4F4F6` |
| 卡片面 | `#FFFFFF`，1px `#E3E3E7` 描边 |
| 强描边 | 1px `#0A0A0A`（用于当前项、卡片选中态） |
| 主文字 / 次文字 / 弱文字 | `#0A0A0A` / `rgba(10,10,10,.56)` / `rgba(10,10,10,.34)` |
| 圆角 | 卡片 16px、小件 10px、图标超椭圆 22% |
| 字重对比 | 主字 700–800，副标 300 斜体（ego / (lite) 的对比逻辑） |
| 角色色 | 策展=橙 `#F2C489`、我的=黄 `#F5DE9A`、自动=蓝 `#A9CBE8`、工具=粉 `#F3C3C0`、中性=灰 `#DCDCDC` |

品牌红 `#fa2d48` 不再使用 —— 那是 Apple Music 的语言，不是 ego 的。ego 的做法是**颜色即角色**：一个颜色只承载一种含义。

## Consequences

- 界面观感与 Apple Music 版不同，这是有意的：ego 风格是"白底卡片 + 黑描边 + 角色色"，克制而工程化。
- 移动端渲染层新增快照与动作接口，架构复杂度上升；换来的是这个 App 可以被 AI 直接驱动与观察。
- 角色色是语义，不是装饰：新增区块时必须先确定它的角色，否则不允许引入新的颜色。

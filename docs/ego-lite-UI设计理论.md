## 0. 一个关键的元观察

**ego-lite 仓库里没有一行 UI 代码。** 它是浏览器自动化的 JS harness（`ego-browser`）+ Agent Skill 包，真正的 Chromium 内核与原生 `ego.snapshot()` 实现闭源，在 ego lite 桌面应用里。

所以「它的 UI 理论」不能按找 CSS/组件的方式去找。正确的问法是：

> **当用户是 AI 模型而不是人时，这套东西把「界面」做成了什么形状？**

答案是：它把浏览器拆成了 **五层界面**，每一层都为不同角色服务，并且刻意区分「人 UI」（浏览器窗口、Space 卡片）与「模型 UI」（Snapshot 文本树、错误文案、API 签名、Skill 手册）。

| 层 | 界面形态 | 消费者 | 核心问题 |
|---|---|---|---|
| L1 空间层 | TaskSpace / Page 所有权状态机 | 人 + Agent | 人和 Agent 如何共用一个浏览器而不打架 |
| L2 感知层 | Snapshot 文本树 + `@N` ref | **模型** | 文本模型如何"看懂"网页 |
| L3 动作层 | locator 文法 + 两阶段协议 | **模型** | 模型如何精确、稳定地指向元素 |
| L4 反馈层 | transient/permanent + 稳定错误码 + hard stop | **模型** | 失败后模型该重试还是换策略 |
| L5 指令层 | SKILL.md 分层披露 + `help()` 自文档 + learnings | **模型** | 上下文预算下如何保持知识可用且不漂移 |

贯穿五层的元原则：**把「界面」从像素搬到 token 与语义上，并把可靠性约束前移到构建期。**

## 1. 五个层级各自的关键设计

### L1 空间层：控制权是一等公民

所有权被显式建模为 `ownership: "agent" | "agentDelegatedToUser" | "user"`，围绕它是一组**语义精确的动词**：`taskSpace` / `claimTaskSpace` / `takeOverTaskSpace` / `handOff` / **`waitForControl`（等待而不夺取）**。

越权即**硬停止**而不是静默失败：硬停止时整轮已缓冲的业务输出被丢弃，只留一段自有指引（"do not retry and do not take control back on your own"）。**当状态已经不可信时，宁可把这一轮输出全部作废，也不让模型基于半截真相继续推理。**

人机共享的界面元素是 `label` —— **模型的动作意图被人看到**。

### L2 感知层：Snapshot 是给模型看的"渲染结果"

- **输出形态是带缩进的纯文本树，不是 JSON**。消费者是语言模型，不是 `JSON.parse`；人类可读 + 高度可压缩 + 无需引号转义，是这个场景的最优解。
- **降噪有红线**：折叠结构的自由度可以很大（无名空容器删除、单子节点容器用子节点替换自身），但**永远不许删改非空页面文本**。折叠结构的自由度，不许动内容本身。
- **Ref 体系**：v2 的 `@N` 极短、可直接粘进脚本、解析支持 `@12` / `ref=12` / `12` 三形态；partial 快照走 `merge`、full 走 `replace`，因此**取一棵子树不会打断上一次全页快照里其它元素的 ref**。
- **失效时给的是下一步动作，不是抱怨**："Stale ref: @N; take a new snapshot"。
- **语义来自无障碍树**（CDP `Accessibility.getFullAXTree`），不是自研 DOM 解析 —— 所以语义选择器跨站点稳定，优先级是：快照 ref > 语义 locator > 裸 CSS。
- **观察是只读的**：捕获快照不得激活、聚焦或 reload 任何 frame。

### L3 动作层：两阶段协议 + 带类型的 locator 文法

工作循环是 **snapshot → 决策 → 动作 → 验证**，不是"看到就点"。locator 前缀即类型：`@21` / `loc=role:` / `loc=css:` / `loc=href:` / `text=` / `xpath=`。

歧义错误带**候选列表 + 可见/隐藏计数 + 下一步建议**；语法错误时回显**完整文法** —— **把接口说明内嵌进错误消息**，模型不需要回头查文档就能自我纠正。

### L4 反馈层：错误按"该怎么办"分类

- `transient` = 0 命中 / 元素还没出现 → 等待循环应该**继续轮询**
- `permanent` = 命中多个（歧义）/ 语法非法 / ref 过期 → **立即大声失败**

这是**面向行动的分类**，不是面向成因的分类。

- **错误码是持久契约，措辞可漂移，按码分支不要按文本分支。**
- 错误消息五要素：期望签名、当前页面状态、候选元素、阻塞原因、下一步动作。超时也要带**阻塞原因**，而不是只带一个数字。

### L5 指令层：在 token 预算里做上下文工程

- **两级 Skill**：入口只留路由（几十 token），完整手册按需拉取，且**永远与已安装的二进制版本对齐** —— 这消灭了"文档漂移"这一整类失效。
- **token 预算写进构建**：`maxGuideLength = 25_000`，超限即构建失败（不是评审期口头约定）。
- **三级渐进披露**：常驻路由 → 按需手册 → 运行时 `help()` 查长尾（`help()` 用 acorn 解析自身构建产物的 JSDoc，文档与代码同源）。
- **教学顺序 = 失败概率降序**：先教怎么把脚本送进去，再教失败归因，最后才教概念。
- **反模式清单：约束优先于示范**。核心是"先归因、再决定"，而不是"失败就重试"。
- **learnings**：知识包禁止使用临时 ref，必须使用稳定 locator；校验器会真的 `import` 工具模块并检查可调用 —— **知识必须是可执行的制品，不是散文**。

## 2. 视觉语言：三个隐喻

仓库只有三张图，但每一张都在表达概念。

- **Logo**：三个黑色实体（大圆、新月、窄透镜）水平排列，既是 "ego" 的几何抽象，也是**被缝隙分开的光圈/瞳孔** —— 光圈是相机隐喻，也是"同一台浏览器里并存多个视口"的空间隐喻。
- **Banner**：字标用 **ego 粗体 + (lite) 细斜体**的对比，"lite" 在视觉上明确弱于 "ego"，却正是它定义了产品形态。3D 高光黑色实体配浅灰渐变底，整体克制单色。
- **架构图**：浏览器窗口内画满 Space 卡片 —— **颜色即角色**：冷蓝=Codex、暖黄=Claude、灰=Cursor、白=人、橙=learnd/RPA、粉=JS runtime。

## 3. 可迁移的十条准则

1. **界面按消费者分层** —— 人看窗口与状态卡片，模型看文本树与错误消息。不要用一套 UI 伺候两种读者。
2. **界面用语义，不用像素** —— role/name 来自无障碍树，跨站点稳定；坐标是最后手段。
3. **观察是只读的** —— 观察带副作用会污染被观察对象。
4. **状态要能被查询，转移要能被命名** —— 杜绝"顺手越权"。
5. **错误按"下一步该干什么"分类** —— transient/permanent 面向行动。
6. **错误码是契约，措辞是实现**。
7. **上下文预算是一条构建期纪律**。
8. **知识分层披露，长尾改查询**。
9. **教学顺序按失败概率排** —— 先教最常坏的地方。
10. **把约束前移成构建错误** —— 越早失败越省 token。

## 4. 方法论：需求即设计

仓库的需求文档格式高度一致：

```
1. 现状与缺口（带具体版本号和失败表现）
2. 要求（祈使句，可执行）
3. 明确不做什么（红线条）
4. Acceptance（可验证的验收条件）
```

验收条件写成**可执行的行为序列**，而不是"应该更好"。未落地的功能被显式记录并标为 **Deferred**，并说明**为什么不做**、**不做会怎样**、**什么时候做** —— 这让"没做"和"忘了做"在仓库里可区分。

还有一条分流规则值得抄：

> 小范围清理可以直接做；**行为或 API 的决定，先写进它所属的设计文档。**

## 6. 一句话总结

> **当界面使用者从人换成模型，就要把整个界面从像素层搬到语义层与 token 层 —— 页面变成一棵带稳定标识的文本树，动作变成有类型的定位器文法，失败变成"下一步该干什么"的指令，而所有这一切的约束，最终都被前移到构建期强制执行。**

三个真正原创的点：**观察层与动作层的身份分离**（ref 短命、locator 稳定）；**hard stop 时作废整轮输出**；**上下文预算与文档漂移被当成工程问题解决**。

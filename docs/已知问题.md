## 2. 退出登录后 `MUSIC_U` 的实际清除未在本机验证

| 项 | 内容 |
|---|---|
| 现象 | 退出登录这条路径，自动化自测只能断言「调了内核的 `logout` 通道」和「界面回到未登录态」；内核 `client.clearAuthCookies()` 是否真的把 `localStorage` 的 `MUSIC_U` 清掉，本机没有真账号可验。 |
| 复现步骤 | 扫码登录 → 顶栏账号 → 退出登录 → 在浏览器控制台查 `localStorage.MUSIC_U`（或内核 cookie jar）。 |
| 当前状态 | `待真机验证`。清理逻辑在内核层（`www/kumone/lib/api.js` 的 `logout()`），移动端侧只调用通道。 |

## 3. 桌面浏览器里必须靠本地 CORS 中继才能拿到真实数据

| 项 | 内容 |
|---|---|
| 现象 | 桌面浏览器直接向 `music.163.com` 发请求会被 CORS 拦掉，界面表现为「网络不可用 / `KUMONE_NETWORK`」。 |
| 复现步骤 | 不起中继，直接用浏览器打开 `www/index.html`。 |

## 10. ego-lite 验收时，窗口在后台会冻结渲染 —— 会造成假 bug

| 项 | 内容 |
|---|---|
| 现象 | 在 ego-lite 里测「吸顶标题收缩」时，先测出**标题不浮现**（`opacity` 恒为 0）、**滚回顶部后状态不恢复**。看起来像两个真 bug。 |
| 复现步骤 | 让 ego 窗口处于后台/被遮挡状态 → 滚动页面 → 读 `getComputedStyle`。 |
| 当前状态 | `设计决定`（不是 App 的缺陷）。窗口不在前台时 Chromium 会冻结渲染与 CSS 过渡，滚动事件也会延迟派发，于是量到的全是「动画起点值」。用 `page.cdp('Page.bringToFront')` 拉回前台后重测：`opacity` 正常到 1、滚回顶部正常恢复。**教训**：任何用浏览器量 CSS 的验收都要先 `bringToFront`；量到「过渡中间值」时先怀疑环境，再怀疑代码。 |

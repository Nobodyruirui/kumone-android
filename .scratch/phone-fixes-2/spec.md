# 第二轮：封面加载 / 迷你条 / 榜单空白 / 转场流畅度

Status: ready-for-agent
Feature: phone-fixes-2

> 上一轮（`.scratch/phone-fixes/`）的四个问题已在真机上验证到新问题。这一轮只处理用户用完第一版后新提的四条。

## Problem Statement

用户装上第一版新包后，用了一会儿，提出四个新问题：

1. **封面加载速度不一致**，有的封面秒出、有的半天不出来；**迷你播放条上根本没有歌曲封面**（是个音符占位图）。
2. **迷你播放条上方那条黑线看着像设计缺陷** —— 它其实是播放进度，但 2px 纯黑顶在卡片圆角上，在高倍屏上是一道粗黑杠。
3. **排行榜里任意一个榜点进去都没有内容**。
4. **左滑切换界面动画不够流畅，切换后新界面加载也不够流畅**。

## Solution

1. **封面**：图片地址统一带**缩略尺寸参数**（几十 KB 而不是几百 KB 的原图），加载失败**自动换 CDN 节点重试**（网易云 p1..p4 四个节点内容相同），列表里的封面**懒加载 + 淡入**，避免「一块块蹦出来」。
2. **迷你条进度线**：按用户选的 A 方案改成**顶部 1px 淡墨细线、两端内缩**，不再顶到圆角；同时迷你条封面走小尺寸（96px）并优先加载。
3. **榜单/歌单详情**：网易云 v6 接口把曲目放在 `playlist.tracks`（移动端从顶层取 → 全空），改为正确取值，并支持「首屏 50 首 + 加载更多」。
4. **转场**：改用 GPU 合成（`translate3d` + `will-change`），**动画先起、内容后填**（不再让 DOM 构建阻塞第一帧），长列表用 `content-visibility` 降低渲染成本，歌词逐帧刷新只在歌词可见时跑。

## User Stories

1. 作为听众，我想所有封面**加载速度一致**，这样界面不会一半有图一半空白。
2. 作为听众，我想迷你播放条**显示真实封面**，这样我能一眼认出是哪首歌。
3. 作为听众，我想封面加载失败时**自动换个节点重试**，而不是直接变成占位图。
4. 作为听众，我想封面出现时是**淡入**的，而不是突然蹦出来。
5. 作为听众，我想迷你播放条上的进度线**精致、不抢戏**，这样它不像设计缺陷。
6. 作为听众，我想点进任意一个**排行榜都能看到曲目**。
7. 作为听众，我想点进**任何歌单**都能看到曲目（不只是榜单）。
8. 作为听众，我想歌单长了能**加载更多**，而不是一口气塞 100 首。
9. 作为听众，我想左滑切换**顺滑不卡顿**，这样滑动跟手。
10. 作为听众，我想新页面**立刻出现并开始加载**，而不是先白一下再出内容。
11. 作为听众，我想长列表滚动**不掉帧**。

## Implementation Decisions

- **缩略尺寸**：图片地址规整函数支持尺寸参数，界面上按用途给尺寸（卡片 220 / 迷你条 96 / 详情头图 400 / 全屏封面 500 / 广播卡 300），请求的都是网易云图片服务现成的裁剪图，不额外下载原图。
- **CDN 节点回退**：封面加载失败时把 `p1..p4.music.126.net` 的节点号轮换重试，最多 3 次；仍失败才落到占位图。回退只发生在图片层，不影响数据。
- **懒加载与淡入**：列表类封面 `loading="lazy"` + `decoding="async"`，加载完成后加一个类做 opacity 过渡；迷你条与全屏封面优先加载（eager）。
- **进度线按 A 方案**：1px、半透明墨色、左右各内缩 14px，不再压在卡片圆角上。
- **歌单详情取数**：服务层从 `playlist.tracks` 取曲目，同时把 `playlist.trackIds` 透出；详情页首屏 50 首，「加载更多」按 id 批量取详情。
- **转场时序**：先把旧内容搬进上一层并**立刻启动动画**，新内容在下一帧构建，避免第一帧被 DOM 构建与图片解码拖住。
- **长列表**：曲目行加 `content-visibility: auto`，让屏幕外的行不参与渲染。
- **歌词帧循环**：只在歌词视图可见时做逐帧计算。

## Testing Decisions

- 沿用既有 seam：Node 纯函数与服务层单测、Edge headless 视图探针、guard 构建闸。
- 新增断言：歌单详情取到曲目（服务层）、封面地址带缩略参数、CDN 回退会换节点、详情页「加载更多」可用、迷你条封面有尺寸参数。
- 真机项（封面速度与动画手感）只能装包后确认。

## Out of Scope

- 不做图片走原生 HTTP 桥的方案（用户已选纯前端）。
- 不做歌单详情的搜索/排序/筛选。
- 不做专辑与歌手页的分页（它们本来就一次性返回）。
- 不改网易云接口与内核层。

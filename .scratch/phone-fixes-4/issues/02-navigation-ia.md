# 02 · 导航改造：资料库移出一级菜单（方案 B）

Status: done
Feature: phone-fixes-4

## Problem

用户报了两条：

- **资料库不要放到一级菜单，一直点错**。
- **还是找不到歌单和收藏位置在哪**（资料库 → 播放列表 / 收藏的专辑，埋了两层）。

## Solution（方案 A 试过，**用户反馈不好用，改成方案 B**）

| 位置 | 放什么 | 行为 |
| --- | --- | --- |
| 底部导航 | 主页 / 广播 / 搜索（**三键**） | 资料库不再是一级菜单 |
| 顶栏左上角 | **常驻**的圆形「我的」图标按钮 | 点开「我的」抽屉 |
| 顶栏右上角 | 账号胶囊（头像 + 昵称 + VIP） | 点它 = **退出登录**（带确认框） |
| 抽屉内容 | 我的歌单 / 收藏的专辑 / 喜欢的音乐 / 云盘 / 最近播放 / 听歌排行 / 退出登录 | 点任一项直接进对应子页 |
| 未登录时右上角 | 「登录」按钮 | 资料库移出一级菜单后，登录路径只剩顶栏这一条 —— 空着就等于把路堵死 |

「我的歌单」与「收藏的专辑」在入口列表里**排最前面** —— 这正是用户报过「找不到」的两个。

### 为什么从 A 改成 B

A 方案是「左上角一次性胶囊，用一次即消失 + 账号胶囊开抽屉」。用户试用后说**不好用**：

- 胶囊只出现一次，太轻，用户不一定注意到；
- 为了让它有意义，还得把退出登录挪进抽屉（反而让右上角头像不直白）。

B 方案把「我的」做成**常驻图标**，一眼可见、随时能进；右上角账号胶囊回归「只管退出登录」，语义直白。

> 用户追问过一句：「A 方案是不是只能进一次歌单，没办法重复进？」
> 答：一次性消失的只是**提示**，歌单本身能反复进。B 方案连提示都不必消失。

## Implementation

- `www/mobile/core/shell.js`
  - `TABS` 从四项减到三项（去掉 library）。
  - 顶栏左槽从「只有返回箭头」变成**二选一**：根页面显示常驻的「我的」图标，有历史时让位给返回箭头。
  - `setAccount()`：账号胶囊回到「退出登录（带确认框）」；未登录时给一个「登录」按钮。
- `www/mobile/core/actions.js`
  - 新增 `M.actions.openMine()`：未登录 → 拉起扫码（`resume:{view:'library'}`）；已登录 → 弹抽屉。
  - 新增 `M.actions.showMineSheet()`。
- `www/mobile/views/library.js`
  - 入口集合抽成 `buildEntries(opts)` —— **页面与抽屉共用这一份**（同一个入口集合写两遍，迟早出现两个真相）。
  - 导出 `M.mine = { ENTRIES, buildEntries, summaryOf }`。
  - 「播放列表」改名「我的歌单」；入口顺序调整为 我的歌单 → 收藏的专辑 → 喜欢的音乐 → …
  - 页面标题「资料库」→「我的」。
- `www/mobile/css/shell.css`：`.m-mine-btn`（常驻圆按钮）、`.m-login-btn`、`.m-list-row-quiet`（退出登录）。

## Acceptance

- `npm run test:mine:entry` —— 绿（新增探针）。
  - 底部导航只有三键、没有「资料库」；
  - 根页面左上角有常驻的「我的」入口，快照里能拿到 ref；
  - 点它开抽屉，里面有「我的歌单」「收藏的专辑」「退出登录」；
  - 抽屉里点「我的歌单」→ 进 myplaylists 视图，抽屉自动收起；
  - 进二级页后左上角让位给返回箭头，回到根页面入口还在；
  - 账号胶囊弹退出登录确认框；
  - 未登录时右上角是「登录」按钮，点它进登录页。
- `npm run test:model` / `test:model-flow` —— 模型侧改成「打开「我的」→ 点喜欢的音乐 → 播放」，绿。
- `npm run test:library` —— 账号胶囊回到退出登录后更新断言，绿。
- `npm run test:try` —— 试用台的 `act` 演示原本硬编码找「资料库」按钮，改为依次找「我的」胶囊 / 「广播」，绿。
- `npm run test:guard` —— 体积上限从 224KB 提到 240KB（新增抽屉 + 入口 + 页面缓存 + 后台播放桥），绿。

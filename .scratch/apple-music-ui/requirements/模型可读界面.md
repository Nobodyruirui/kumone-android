# 模型可读界面

> 载体：`.scratch/apple-music-ui/requirements/模型可读界面.md`
> 决策依据：`docs/adr/0003-双模态界面与ego视觉语言.md`（§1 界面按消费者分层 / §2 界面用语义不用像素 / §3 观察是只读的 / §4 状态可查询、转移可命名 / §10 约束前移成构建错误）
> 理论来源：`docs/ego-lite-UI设计理论.md`（L2 感知层 / L3 动作层）
> 对应 ticket：`.scratch/apple-music-ui/issues/12-model-readable-ui-and-refs.md`

## 1. 现状与缺口

- 感知层与动作层**已经实现**：`www/mobile/core/snapshot.js` 提供 `Mobile.snapshot()` 与 `Mobile.act(ref, action, args)`（`:263-264` 导出）。
  - ref 分配与复用 `refFor`（`:28-36`）、ref 解析与过期判定 `resolve`（`:39-53`，报 `KUMONE_STALE_REF`）。
  - 语义抽取 `extract`（`:131-169`）：标签→角色映射 `:58-64`、可交互角色集合 `:67`、`roleOf()` 显式 `role` 优先 `:69-73`、容器角色只认 ARIA `:84`、无障碍名 `explicitName` `:87-97`、折叠规则与「非空文本不被删改」红线 `:128-129`。
  - 渲染输出 `renderNode`（`:173-185`）、快照入口 `snapshot`（`:191-217`）、上下文头 `[view "..." | refs live]`（`:214`）。
  - 动作白名单 `ACTIONS`（`:221-229`，`click` / `scroll` / `focus` / `fill`）、动作执行 `act`（`:235-261`，白名单外报 `KUMONE_UNSUPPORTED`）。
- **只读已经是真的**：`refFor` 用 `WeakMap` 保存 element → ref（`:21`），**不往 DOM 写任何东西**（`:26` 的注释明确写了这一点）；快照根取 `document.body`（`:195`），否则模型看不到挂在 body 上的底部导航与迷你播放条；`live` 映射在每次快照时清理已卸载节点（`:211`）。回归测试：`test/snapshot-readonly.mjs`、`test/model-actions.mjs`。
- 预览侧已能读到这棵树：`.scratch/apple-music-ui/preview-harness.html:36-38` 在 iframe 里调 `M.snapshot()` 并渲染 `snap.tree`。
- **缺口一：核心层没有 locator API。** role + name 的匹配实现在知识包 `www/mobile/learnings/netease/tools/locator.js`（`parseTree` `:104-140`、`findMatches` `:200-213`、`candidateNames` `:216-226`），也就是说**稳定定位只在「加载了知识包」时可用**；`Mobile.snapshot()` / `Mobile.act()` 本身只认 ref。ADR-0003 §2 规定的「快照 ref > 语义 locator > 裸 CSS」三层优先级，模型侧目前只用到第一层。
- **缺口二：视图重建让 ref 断裂。** `www/mobile/core/router.js:52-58` 的 `M.render()` 每次执行 `root.textContent = ''` 再重建 `#m-view`，因此同一语义元素在切换视图后是**新的 DOM 节点**、新的 ref。`resolve()` 能正确报 `KUMONE_STALE_REF`（`snapshot.js:39-53`），但这只把「静默失败」变成「明确报错」，没有提供稳定的重新定位手段。
- **缺口三：语义标签覆盖不全。** `www/mobile/views/home.js:20` 的区块用了 `role="region"` + `aria-label`（正确示范），但 `home.js:44-52` 的区块内容全是 `skeletonGrid` 占位（`:27-36`），模型读不到真实内容；`www/mobile/views/library.js:37` 又把 `role="listitem"` 压在 `<button>` 上，快照里该节点的角色与实际可交互性不符（`snapshot.js:69-73` 的 `roleOf()` 显式 `role` 优先）。
- **缺口四：核心层与知识包可能各写一套匹配。** 若两边分别实现 role + name 匹配，语义契约就会出现两个真相 —— 与 ADR-0003 §10「约束前移成构建错误」要防的正是这类事。
- **缺口五：没有「按码分支」的自测。** `snapshot.js` 与 `errors.js` 都按码分支，但没有任何断言能证明**调用方**看的是 `err.code` 而不是 `err.message`。
- **缺口六：没有「禁裸 CSS 选择器」的闸。** 现状里 `www/mobile/core/shell.js:94` / `:127` 有两处裸选择器（属「实现内部面」），而规则本身也没划「模型定位面 / 实现内部面」的边界。

## 2. 要求

- 让 `Mobile.snapshot()` 保持为模型侧唯一的观察入口，返回当前界面的语义文本树（带缩进的纯文本，不是 JSON），上下文头沿用 `[view "..." | refs live]`（`snapshot.js:214`）。
- 让同一元素在同一视图内重复快照时 ref 保持不变（由 `WeakMap` + `test/snapshot-readonly.mjs` 保障，不得回退）。
- 让**核心层**暴露一层稳定 locator：支持按 role + name 定位（例如 `loc=role=button[name="资料库"]`），使视图重建后语义上同一个元素能重新解析到等价目标。知识包 `www/mobile/learnings/netease/tools/locator.js` 已有的匹配能力应被提升到核心层或由核心层复用，**不允许两处各写一套**。
- 让 locator 的解析优先级高于裸 CSS 选择器；坐标是最后手段，本轮不提供坐标定位。
- 让降噪遵守红线：可折叠结构（无名空容器删除、单子节点容器用子节点替换自身），但**永远不许删改非空页面文本**（`snapshot.js:128-129`）。
- 让 `Mobile.act()` 的动作严格受白名单约束（`click` / `scroll` / `focus` / `fill`）；白名单外的动作必须返回 `KUMONE_UNSUPPORTED` 并在 `cause` 段列出可用动作（沿用 `snapshot.js:243-248` 的现有做法），**不得静默忽略**。
- 让观察保持只读：`snapshot()` 不改变播放状态、不发请求、不改焦点、**不写 DOM**；维持 `test/snapshot-readonly.mjs` 为回归闸，并把「不写 DOM」纳入断言。
- 让状态可查询、转移可命名：播放状态由 `player.state()` 查询，转移由 `play` / `pause` / `seek` / `next` / `prev` / `queue` / `setQuality` 表达；不允许通过直接改 DOM 来模拟状态变化。
- 让所有可交互元素使用语义标签并带 `aria-label`；修正 `www/mobile/views/library.js:37` 这类角色与可交互性不符的写法。
- 让错误分支**按码分支**：调用方一律依据 `err.code` / `err.kind` 决定下一步，禁止按消息文本分支。
- 让「模型定位面禁止裸 CSS 选择器与硬编码坐标」成为构建期失败项，并先划清它与「实现内部面」的边界。
- 补齐 Node 自测：ref 复用、ref 过期报 `KUMONE_STALE_REF`、非白名单动作报 `KUMONE_UNSUPPORTED`、错误消息五要素齐全、快照不改变播放状态/不发请求/不改焦点/不写 DOM、locator 能跨视图重建重新命中；并接入 `package.json` 的 npm script。

## 3. 明确不做什么

- 不为模型提供「直接改 DOM」的接口；状态转移只走命名动词。
- 不提供像素坐标定位；坐标是最后手段，本轮不引入。
- 不把 `www/mobile/core/snapshot.js` 重写成通用浏览器自动化框架；它只服务本 App。
- 不把逐字歌词页与手势动作纳入动作白名单（两者均为 Deferred，见 spec 的 D1 / D2）。
- 不在知识包（`www/mobile/learnings/`）里收录任何临时 ref —— 那是 ticket 14 的范围，与本 ticket 的「稳定 locator」互补而非重叠。
- 不让知识包与核心层各写一套 role + name 匹配。

## 4. Acceptance

- [ ] 在浏览器控制台执行 `Mobile.snapshot()`，返回对象含 `ok: true`、`scope: 'full'`、`tree`；tree 首行是 `[view "home" | refs live]`，后续为带 role 与 name 的缩进节点。
- [ ] 连续执行两次 `Mobile.snapshot()`，确认同一元素两次 ref 相同（两次输出中都出现 `button "资料库" [ref=@12]`）。
- [ ] 用上一步的 ref 执行 `Mobile.act("@12", "click")`，返回 `{ ok: true, action: 'click', ref: '@12', role: 'button', name: '资料库' }`，且界面发生对应变化。
- [ ] 切走视图使原元素被卸载，再执行 `Mobile.act("@12", "click")`，返回 `ok: false`、`code === 'KUMONE_STALE_REF'`、`kind === 'permanent'`，且 message 的 `Next` 段给出「重新取一次快照：Mobile.snapshot()」。
- [ ] 执行 `Mobile.act("@12", "swipe")`，返回 `ok: false`、`code === 'KUMONE_UNSUPPORTED'`，且 message 的 `Blocked by` 段列出 `click / scroll / focus / fill`。
- [ ] 用 role + name 的稳定 locator 定位「资料库」导航项并点击，确认无需记住上一次的 ref 也能命中同一元素；**且该 locator 由核心层提供，不要求额外加载知识包**。
- [ ] 切换一次视图（触发 `M.render()` 重建）后，用同一 locator 重新命中「资料库」，确认仍能命中 —— 这是「ref 会断但 locator 不断」的直接证据。
- [ ] 执行 `Mobile.snapshot()` 前后各读一次播放状态，确认两次读数**完全一致**；调用期间 Network 面板**无新增请求**；`document.activeElement` 未改变；**DOM 未被写入**（不产生 `data-mref` 之类的标记属性）。
- [ ] 逐项比对模型快照与页面实际可见文本，确认快照中的非空文本与页面一致，未被降噪规则删改。
- [ ] 在 `www/mobile/` 中检索硬编码坐标（`getBoundingClientRect` 配固定数字、`clientX` / `clientY` 固定值），确认无命中。
- [ ] 执行 snapshot 与 locator 自测脚本，确认上述断言全部 PASS；确认它已接入 npm script，可一条命令跑完。
- [ ] 在 `docs/adr/0003` 或本文件中找到「模型定位面」与「实现内部面」的明确边界结论（允许实现内部使用选择器，但需显式登记）。

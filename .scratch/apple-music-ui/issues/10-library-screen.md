# 10: 资料库页与账号入口

**Blocked by:** 06: 扫码登录, 07: 底部导航与吸顶标题接线

**Status:** done

## 现状与缺口

- `www/mobile/views/library.js` 已实现**分段入口的骨架**：`:7-13` 定义了五个入口（播放列表 / 喜欢的音乐 / 云盘 / 最近播放 / 听歌排行），每个入口带一个角色色点（策展=橙、我的=黄、中性=灰、自动=蓝），`:34-41` 渲染为 `<button role="listitem" aria-label="...">` 列表行。
- **具体缺口**：五个入口**全是死的** —— `:43` 的点击处理只弹一句 `M.shell.toast(e.label + ' 将在后续版本开放')`，不请求任何数据、不进入任何列表。
- **具体缺口**：没有「我的歌单」与「喜欢的音乐」之外的**二级列表视图**。`M.views`（`www/mobile/core/router.js:10`）里没有歌单详情 / 歌曲列表 / 云盘列表这类视图类型。
- **具体缺口**：没有账号区。`www/mobile/core/shell.js:49` 已经预留了 `#m-header-right` 容器，但**没有任何东西往里写**；账号头像与昵称没有任何落点。
- **具体缺口**：没有退出登录。内核层有 `www/kumone/lib/api.js:38` 的 `logout()`，但移动端侧无人调用；`localStorage` 的 `MUSIC_U`（`AGENTS.md` 的登录约定）也没有清除路径。
- **具体缺口**：没有未登录分支。当前点「资料库」会看到一个**看起来正常但点不动**的列表 —— 这比直接拉起扫码更糟：用户会以为应用坏了。
- **具体缺口**：`role="listitem"` 被放在 `<button>` 上（`www/mobile/views/library.js:37`）。按无障碍语义，`listitem` 应是 `list` 的子项、可交互性由 `button` 角色承担；ADR-0003 说「无障碍树就是界面契约」，这个组合在模型快照里会产生一个角色不准确的节点 —— `www/mobile/core/snapshot.js:69-73` 的 `roleOf()` 显式 `role` 优先，会输出 `listitem` 而不是 `button`，模型据此判断「可交互元素」时会失真。

## 要求

- 让资料库以分段入口呈现：播放列表 / 喜欢的音乐 / 云盘 / 最近播放 / 听歌排行。
- 让点击任一入口进入对应列表，并可播放其中内容（播放经 ticket 05 的播放引擎，列表数据经 ticket 04 的服务层）。
- 让右上角 `#m-header-right` 显示账号头像与昵称，点击可退出登录。
- 让未登录时点击资料库**直接拉起扫码登录**，而不是渲染一个点不动的列表。
- 让未登录状态下各入口显示登录引导，而不是空列表。
- 让退出登录后清除本地登录态（`localStorage` 的 `MUSIC_U`），回到未登录态。
- 让五个入口在数据就绪后带各自的计数或内容摘要，且角色色保持「颜色即角色」：播放列表与喜欢的音乐 = 我的（黄）、云盘 = 中性（灰）、最近播放 = 自动（蓝）、听歌排行 = 策展（橙）。
- 让每个入口与列表项用语义标签 + `aria-label`，让模型侧能在快照里读到「喜欢的音乐」这类语义名并据此点击。
- 核对并修正入口行的无障碍角色组合，使快照里的角色与实际可交互性一致。
## 明确不做什么

- 不在本 ticket 里实现资料库内部的独立子页面体系（收藏夹管理、新建歌单、编辑歌单信息、云盘上传）。
- 不实现账号设置页、账号资料编辑、多账号切换。
- 不实现搜索页与广播页（占位页见 ticket 07）。
- 不在资料库里直连内核接口，一律经服务层；退出登录时对内核的 `logout()` 调用可由服务层承接。

## Comments

资料库是**登录能力的主要落点**：它既是「我的内容」入口，也是账号区所在。spec 里「未登录时点击资料库，直接拉起扫码登录，而不是把我丢到一个空页面」这条故事，本 ticket 就是它的实现处。

三个落地要点：

1. **未登录分支要在「点资料库」这一刻生效，不是进入资料库后再判断。** 现在 `www/mobile/views/library.js:43` 每个入口点击都弹 toast，说明未登录态被当成了「功能没做完」，而不是「需要登录」。两者要区分开。
2. **角色色不要新增。** 五个入口的角色色已在 `www/mobile/views/library.js:9-12` 定好（owned / owned / neutral / auto / curated），与 `www/mobile/css/shell.css:298-307` 的角色色映射一致。资料库属于「我的」，但**云盘是中性、最近播放是自动、听歌排行是策展** —— 一个颜色只承载一种含义，不要为了「整页统一」把五个点涂成同一个黄。
3. **无障碍角色要核对。** `www/mobile/views/library.js:37` 现在给 `<button>` 配了 `role="listitem"`，模型快照里这个节点的角色会失真（`www/mobile/core/snapshot.js:69-73` 的 `roleOf()` 显式 `role` 优先）。ADR-0003 要求「role+name 来自无障碍树，是跨站点稳定的契约」，所以这里要么让按钮保持 button 角色、由外层 `role="list"`（`:35`）承担列表语义，要么换用 `<li>` 包 `<button>`。两种都可以，但必须让快照里的角色与实际能点的事实一致。

账号区落在 `www/mobile/core/shell.js:49` 已预留的 `#m-header-right` 里，不要另起容器。

### 本轮落地结论

- **落点**：
  - `www/mobile/views/library.js`（重写）—— 资料库入口页：五个入口 + 异步摘要 + **guard**。
  - `www/mobile/views/mylist.js`（新）—— 五个二级列表：我的歌单 / 喜欢的音乐 / 云盘 / 最近播放 / 听歌排行，共用一份实现。
  - `www/mobile/core/router.js` —— `goTab` 支持视图的 **guard 钩子**：视图可以先决定「我能不能进」。
  - `www/mobile/core/shell.js` —— 账号区 `setAccount()` + 可复用确认弹窗 `confirm()`。
  - `www/mobile/core/actions.js` —— `refreshAccount()` / `confirmLogout()`。
  - `www/mobile/core/player.js` —— 新增**本机播放历史**（`history()` / `clearHistory()`，持久化键 `mobile.history`，上限 50 首）。
- **未登录直接拉起扫码**：靠 guard 实现 —— 点底部导航「资料库」时先问 `isLoggedIn()`，未登录就 `M.actions.toLogin({view:'library'})` 并**不渲染入口列表**。guard 返回 false 表示「我已经把你带到登录页了」，路由器就不再切视图。
- **登录后送回资料库**：扫码成功时若带 `resume:{view:'library'}`，直接落到资料库（而不是退回上一页）；没有 resume 才退回栈里那个视图。
- **摘要**：五个入口各自异步取数补摘要（12 个歌单 / 128 首红心 / 云盘 3 首 / 本周 30 首），取不到就写「加载失败」并把错误码挂在 `data-code` 上 —— 不假装有数据。
- **角色色不新增**：播放列表与喜欢的音乐=我的（黄）、云盘=中性（灰）、最近播放=自动（蓝）、听歌排行=策展（橙）。
- **无障碍角色修正**：入口行改成 `<li role="listitem"><button>`，快照里角色是 `button`（可点、能拿 ref），列表语义由外层 `ul[role=list]` 承担。
- **账号区**：顶栏右上角显示头像 + 昵称（`#m-header-right`，没另起容器）；点击弹**自定义确认框**（不是 `window.confirm` —— 原生弹窗在 WebView 里体验差）；确认后调内核 `logout()` 清 `MUSIC_U`，账号区清空、界面回主页。
- **「最近播放」与「听歌排行」刻意用两套数据源**：
  - 最近播放 = **本机**播放历史（播放器记的，`mobile.history`），不发请求；
  - 听歌排行 = 服务端按周统计（`playRecords(uid, week=true)`），带播放次数。
  两者如果都用服务端的记录，就成了同一份数据的两个名字。
- **自测**：`test/library-view.mjs`（`npm run test:library`）+ 探针 `test/fixtures/probe-library.html`。五个场景：未登录拉起扫码、已登录五入口与 ref、点播放列表进歌单列表、点喜欢的音乐进曲目列表、账号区与退出登录。
- **踩过的坑**：
  - 假服务的 `account()` 永远返回账号，导致「退出登录后顶栏账号区清空」这条断言测不出真实行为。假服务必须**跟真行为一致**（退出之后 `account()` 要报错），否则测试是自欺欺人。
  - **异步竞态**：应用启动时会读一次账号（真实网络，慢），它可能在用户登录之后才返回，把顶栏账号区**清空**。修法是给账号刷新加令牌，只有最后发起的那次能写界面。
  - **浏览器缓存**：浏览器探针如果复用同一个 `--user-data-dir`，Edge 会拿缓存里的旧页面跑 —— 表现为「改了代码但测试结果没变」。这个坑真踩过一次（改了探针页，浏览器还在跑旧的那份，误以为实现有 bug）。现已统一到 `test/browser.mjs`：每次用全新 profile 目录。

# 14: 知识包与构建期约束

**Blocked by:** 12: 模型可读界面与稳定ref体系, 13: 错误契约与稳定错误码

**Status:** ready-for-agent

## 现状与缺口

- ADR-0003 §7 / §8 / §10 规定的机制**已经落地了一部分**：
  - **知识包**：`www/mobile/learnings/netease/` 已存在，含 `manifest.json`（声明 `entry.loadOrder`、locator 文法 `role+name`、被禁用的定位形式、动作白名单、错误码说明）、三个可执行工具（`tools/locator.js` / `tools/playlist.js` / `tools/playback.js`）、三篇说明（`notes/locators.md` / `notes/sections.md` / `notes/playback.md`）。入口 `www/index.html:38-40` 按 `loadOrder` 加载。
  - **知识包校验器**：`test/validate-learnings.mjs` 已实现 —— 禁临时引用扫描（`:57-70`）、manifest 与工具文件校验、**真的 require 并调用**每个工具（`checkExports` `:87-107`、`smokeCall` `:109`），确认导出是可调用的异步函数。
  - **构建期闸**：`test/guard-design.mjs` 已实现四条 —— 体积闸（`LIMITS` `:39-43`：CSS 48KB / JS 80KB / 字体 128KB）、临时 ref 禁令（`:64-76`）、错误码 `kind` 完整性（`:78-93`）、aria 语义契约（`:95-109`）。
  - **回归测试**：`test/snapshot-readonly.mjs`（只读）、`test/model-actions.mjs`（动作层与错误契约）、`test/learnings-browser.mjs`（知识包接进应用后可用）三个浏览器侧探针齐备；`package.json` 已有 `test:guard` / `test:readonly` / `test:model` / `test:learnings` / `test:learnings:browser` 五个入口。
- **具体缺口一**：**没有「禁裸 CSS 选择器」**。ADR-0003 §2 与 §10 都点名了它，但 `guard-design.mjs` 的四条闸里没有这一条 —— 所以 `www/mobile/core/shell.js:94` 的 `document.querySelectorAll('#m-nav .m-tab')` 与 `:127` 的 `document.querySelector('#m-mini-line > i')` 不会被拦。**更关键的是规则本身没划边界**：这两处属于「实现内部面」（外壳操作自身 DOM），而规则若一刀切会逼着开发者写更绕的代码而不是遵守规则。必须先定义「模型定位面」与「实现内部面」，再落成检查。
- **具体缺口二**：**没有「禁界面层直接改状态」**。ADR-0003 §10 点名的三类违规里，「裸 CSS 选择器」与「临时 ref」已落地两条，**「界面层直接改状态」这一条没有对应闸门**（例如视图里直接赋 `Mobile.player.state().index = 0` 不会被拦）。
- **具体缺口三**：**没有「禁按文案分支」**。ADR-0003 §6 要求按码分支，但 `test/` 下没有任何检查会因 `err.message.includes(...)` 式的分支而失败（与 ticket 13 共同承接）。
- **具体缺口四**：**体积闸量的不是上下文预算**。`guard-design.mjs:39-43` 量的是 `www/mobile` 目录的**字节数**（安装包体积），而 ADR-0003 §7 说的是「上下文预算」—— 即模型侧一次要读进去的**文本量**（快照树 + 知识包 + 文档）。两者不是一回事，前者已有、后者缺失。
- **具体缺口五**：**知识包条目没有失效标记与替代路径**。`notes/*.md` 里没有失效字段，`validate-learnings.mjs` 也不检查它；页面或接口改版导致某条 locator 失效时，仓库里没有地方能标记它。
- **具体缺口六**：**「四处同步」没有检查**。ADR-0003 要求「schema → 实现 → 回归测试 → 文档」四处同步，目前没有任何机制保证这四处不会漂移 —— 错误码表已经出现三份（`www/mobile/core/errors.js:15-29`、`www/mobile/learnings/netease/tools/locator.js:35-41`、`www/mobile/learnings/netease/manifest.json:39-43`），就是这项缺失的直接后果。
- **具体缺口七**：**知识包与核心层各有一套匹配实现的风险**。role + name 的匹配实现在 `www/mobile/learnings/netease/tools/locator.js`（`parseTree` `:104-140`、`findMatches` `:200-213`），而核心层 `www/mobile/core/snapshot.js` 没有 locator API（ticket 12）。若两边各写一套，语义契约就会出现两个真相。
- **具体缺口八**：**没有「一条命令跑完全部约束」的入口**。`package.json` 里六条测试入口是分开的，没有聚合脚本。

## 要求

- 保留并加固 `www/mobile/learnings/` 知识包：每条知识是**可执行的制品**（能被程序加载并校验），不是一个散文的说明段落；入口继续按 `manifest.loadOrder` 加载（`www/index.html:38-40`）。
- 让知识包**只允许稳定 locator，禁止临时 ref**：任何以 `@N` 形式出现的定位符出现在知识包里都算失败（`validate-learnings.mjs` 已有此规则，需保持）。
- 让知识包**与核心码表逐码对齐**：`www/mobile/learnings/netease/tools/locator.js:35-41` 的 `TITLES` 与 `www/mobile/learnings/netease/manifest.json:39-43` 的 `errorCodes` 必须与 `www/mobile/core/errors.js:15-29` 一致，不允许知识包自持一份「同构但独立」的码表（与 ticket 13 共同承接）。
- 定义并写下「稳定 locator」的判定标准：按 role + name 定位、跨站点/跨版本稳定、失效时有明确原因与替代路径；把标准写成知识包文件头部的一条规则。
- 让**每条知识可被程序验证**：校验器真的加载知识条目引用的模块并检查其可调用性，不接受「写在文档里就算数」（已实现，需保持并扩展到每条 `notes/*.md` 的定位表）。
- 新增**上下文预算闸**：把模型侧一次要读入的**文本量**（快照树 + 知识包 + 文档）的上限写进自测，超限即失败；与现有的目录字节体积闸并列，两者不是一回事。
- 新增**禁裸 CSS 选择器**的自测，并**先划清「模型定位面」与「实现内部面」的边界**：模型定位面（供快照 / 动作 / 知识包使用的定位）禁止裸 CSS 选择器与硬编码坐标；实现内部为了操作自身 DOM 所需的选择器允许存在，但必须显式登记（集中到被允许的位置或加豁免注释），不得静默扩散。
- 新增**禁界面层直接改状态**的自测：视图层直接改播放/导航状态即失败。
- 新增**禁按文案分支**的自测：检索 `www/mobile/` 全目录中对 `message` / `title` 做包含判断来决定行为的写法并报失败（与 ticket 13 共同承接）。
- 让知识包条目带失效策略：页面或接口改版导致某条 locator 失效时，条目被显式标记为失效并给出替代路径，而不是留着误导模型；校验器检查该字段存在。
- 让「schema → 实现 → 回归测试 → 文档」四处同步成为可检查项：当错误码表、动作白名单、快照形态或知识包发生变化时，缺少对应的一处即失败。
- 让「一条命令跑完全部约束」成为可能：在 `package.json` 增加聚合脚本（体积闸 + 违规检测 + 知识包校验 + 四处同步 + 全部 Node 自测），任一环节失败即整体失败。
- 让体积闸与上下文预算闸的**上限值先取当前基线**并写进闸内，超限时的处理方式是「减内容或显式改上限并留下决策记录」，不是静默放宽。

## 明确不做什么

- 不把长尾的网易云接口细节写进常驻文档；接口契约属内核层，页面定位器属知识包，长尾细节通过查询获取。
- 不为知识包引入第三方依赖或构建步骤；校验器用仓库既有的 Node 脚本风格（无测试框架、无新依赖）。
- 不在知识包里收录临时 ref、`@N` 或硬编码坐标，即使它当下能用。
- 不因为闸门超限而放宽上限；超限要么减内容，要么改上限并留下决策记录。
- 不把知识包的匹配实现与核心层的 locator 实现写成两份；两者必须共用一份（与 ticket 12 共同承接）。
- 不在闸门里禁止实现内部的一切选择器 —— 那会让规则不可执行；只禁模型定位面。

## Acceptance

- [ ] `www/mobile/learnings/` 存在，且其中每条知识都能被校验器加载并通过校验；校验器**真的调用**知识条目引用的可调用物（不是只检查文件存在）。
- [ ] 在知识包里故意写入一条带 `@N` 的定位符，确认校验失败并指出文件与行号；改回稳定 locator 后通过（反向验证检测器有效）。
- [ ] 在知识包里写入一条引用了不可调用模块的条目，确认校验失败并报出「不可调用」。
- [ ] 在知识包里改一个错误码的标题，确认**与核心码表的逐码比对**失败并指出文件与行号；改回后通过（反向验证一致性检测器有效）。
- [ ] 执行体积闸，确认在超过设定上限时**失败**并报出实际体积与上限；把上限调低到当前体积以下再跑一次确认会失败，随后调回（反向验证闸门有效）。
- [ ] 执行上下文预算闸，确认它量的是**模型侧文本量**而非目录字节数；超过上限时失败并报出实际量与上限。
- [ ] 在模型定位面写一处裸 CSS 选择器定位，确认自测失败并指出文件与行号；改回 role + name 后通过。
- [ ] 确认**实现内部面**（`www/mobile/core/shell.js:94` / `:127` 这类外壳操作自身 DOM 的选择器）不被误伤，但未登记的新增选择器会失败 —— 两面都必须有可执行的判定。
- [ ] 在 `www/mobile/views/` 或 `www/mobile/core/` 里写一处「界面层直接改状态」（例如视图里直接赋 `Mobile.player.state().index = 0`），确认自测失败并指出文件与行号；改回后通过。
- [ ] 写一处按 `err.message` 文案分支的代码，确认自测失败并指出文件与行号（与 ticket 13 共同承接）。
- [ ] 修改错误码表新增一个码但不更新回归测试，确认「四处同步」检查失败并指出缺失的是回归测试那一处；补齐后通过。
- [ ] 确认知识包条目带失效标记字段，并确认校验器会检查该字段存在；标记某条失效后，校验器给出明确提示而不是静默通过。
- [ ] 确认 `package.json` 里有一条聚合命令能一次跑完全部约束（体积闸 + 上下文预算 + 违规检测 + 知识包校验 + 码表一致性 + 四处同步 + 全部 Node 自测），且任一环节失败时整体失败。

## Comments

本 ticket 是 ADR-0003 §7 / §8 / §10 的落地载体，也是「知识包」这个概念在本仓库的实体化。现状比预想的靠前：**知识包、校验器、体积闸、临时 ref 禁令、错误码 kind 检查、三个浏览器回归测试都已经有了**（见「现状与缺口」列出的行号）。所以本 ticket 剩下的不是「从零建机制」，而是**补齐三类违规里漏掉的两条 + 加两个新闸 + 收口漂移**。

四个需要先想清楚的点：

1. **「禁裸 CSS 选择器」必须先划边界，否则不可执行。** `www/mobile/core/shell.js:94` 与 `:127` 的选择器是外壳操作自身 DOM 的正常实现。若规则一刀切，会逼着开发者去写更绕的代码而不是遵守规则。落地时要明确：**模型定位面禁止，实现内部面允许但需显式登记**。ADR-0003 §2 目前只写了「禁止裸 CSS 选择器与硬编码坐标」，没写边界 —— 这条边界建议同步补进 ADR，否则每个 Agent 都会重新纠结一遍。
2. **体积闸与上下文预算闸不是一回事。** 现有的 `guard-design.mjs:39-43` 量的是安装包字节数（有用，但不是 ADR-0003 §7 说的那个）。上下文预算量的是模型一次要读入的**文本量** —— 快照树 + 知识包 + 文档。ego 的参考值是 `maxGuideLength = 25_000`（token 预算）；本仓库没有这个概念，所以第一步应当是**先量当前值并写成基线**，再讨论它是否合理。
3. **四处同步的缺失已经造成实际损害。** 错误码表现在有三份（核心 / 知识包工具 / 知识包 manifest），且没有任何校验器对齐它们。「四处同步」不是一条形式主义的要求，它已经有反例了 —— 本 ticket 的第一个实质产出应当就是这条逐码比对。
4. **知识包第一条应该是「怎么跑起来、怎么登录」。** ego 的教学顺序按失败概率降序（`docs/ego-lite-UI设计理论.md` §5），先教归因、再教动作。本仓库的等价物是：扫码登录的稳定定位器、资料库五个入口的 locator、播放页几个控件的 locator —— 这些是模型最常需要、也最容易写错的部分。当前 `notes/` 的三篇（locators / sections / playback）方向是对的，补失效标记时按这个优先级来。

另外，「知识必须是可执行的制品」这条意味着知识包里不能只有 Markdown。若某条知识暂时只能用散文描述（例如「这个页面结构没有稳定 locator」），它应当被明确标注为**未固化的长尾**并指向查询路径，而不是伪装成一条可执行的 locator。

# 08: 主页

**Blocked by:** 04: 移动端服务层, 07: 底部导航与吸顶标题接线

**Status:** done

## 现状与缺口

- `www/mobile/views/home.js` 目前是**纯骨架**：`:44-52` 渲染了「每日推荐」「为你推荐」「排行榜」三个区块，每个区块的内容都是 `skeletonGrid(2, ...)`（`:27-36`）生成的灰色占位块，没有任何真实数据、也没有任何点击行为。
- **具体缺口**：区块**数量与顺序都不对**。spec 要求的是五块：每日推荐大卡 → 横向推荐歌单 → 排行榜 → 推荐歌手 → 新碟上架；当前只有三块，且缺「推荐歌手」与「新碟上架」，第二块标题是「为你推荐」而非「推荐歌单」。
- **具体缺口**：没有加载占位与错误态的区分。当前 `skeletonGrid` 是**永久**占位 —— 它不知道数据是「还没来」还是「失败了」，因此网络失败时用户看到的是**永远转圈的骨架**，而不是明确的错误提示。
- **具体缺口**：没有错误消费路径。`www/mobile/core/errors.js` 已经能产出带五要素与稳定码的错误，但 `www/mobile/views/home.js` 里没有任何一处引用 `M.errors`。
- **具体缺口**：没有未登录分支。每日推荐与推荐歌单需要登录才有内容，当前没有「登录引导」这一态。
- **具体缺口**：区块标题用了 `role="region"` + `aria-label`（`www/mobile/views/home.js:20`），符合 ADR-0003 的语义契约；但区块内的可交互元素（歌单卡、榜单项、歌手卡）一个都没有，因此**模型侧无从定位**这些元素（`www/mobile/core/snapshot.js` 的快照里没有它们）。
- **具体缺口**：没有 `.m-card` 本体样式可依附 —— `www/mobile/css/shell.css:298-307` 只定义了 `.m-card[data-role=...]` 的背景色变体（ticket 02 的待办）。

## 要求

- 让主页按顺序呈现五个区块：每日推荐大卡 → 横向推荐歌单 → 排行榜 → 推荐歌手 → 新碟上架。
- 让每个区块在数据返回前显示**加载占位**（区分于错误态与空态），而不是一片空白。
- 让任一区块请求失败时，只在该区块内显示错误提示与重试入口，不影响其他区块渲染，也不整页失败。
- 让区块失败提示遵守 ADR-0003：错误按 `code` 分支呈现，`transient` 类给「重试」动作，`permanent` 类给「换策略」的动作（如去登录），错误消息含五要素而不是一句「加载失败」。
- 让未登录时每日推荐与推荐歌单区块显示登录引导，点击可拉起扫码（与 ticket 06 的登录中断共用同一条路径）。
- 让横向歌单卡可左右滑动，并支持点进歌单详情。
- 让排行榜项与歌手卡可点击进入对应详情，且进入后底部导航的当前项仍正确（`www/mobile/core/shell.js:93` 的回落规则要一并核对）。
- 让所有可交互元素用语义标签 + `aria-label`，让区块标题、卡片名、歌单名都能出现在模型侧快照里（ADR-0003：无障碍树即契约）。
- 让区块角色色按 ego 规则落位：策展类区块（每日推荐、推荐歌单、排行榜）用橙、我的类用黄、自动类用蓝、中性类用灰；不引入新的颜色。

## 明确不做什么

- 不在本 ticket 里实现歌单详情、专辑详情、歌手详情页的**完整内容**，只负责从主页进入并保证落点存在（内容归 ticket 10 承接）。
- 不在主页做搜索，也不实现广播页。
- 不在主页区块里做无限滚动或分页加载，本轮只做首屏区块。
- 不在主页直接调用网易云接口，一律经服务层（ticket 04）。

## Comments

主页现在是一个**好看但空洞的骨架**，缺的不是样式而是「状态机」：加载中 / 有数据 / 出错 / 未登录 / 空结果，五种态现在只有一种（骨架）。

落地时的三个要点：

1. **加载占位、错误态、空态必须是三个不同的渲染分支。** 现在的 `skeletonGrid` 是静态生成的，必须由区块自己的状态驱动。
2. **错误按码分支，不按文案分支。** `www/mobile/core/errors.js` 已经在 `make()` 里带了 `kind`（`transient` / `permanent`），区块只要看 `err.kind` 与 `err.code` 决定给哪个动作即可，不要 `if (msg.includes('登录'))` 这种写法。
3. **五个区块 ≠ 五个区块。** 顺序里前两块要登录态才出内容，所以「未登录」不是全页状态，而是**局部状态** —— 只有每日推荐与推荐歌单这两块显示登录引导，排行榜 / 推荐歌手 / 新碟仍应正常显示。这一点写清楚，否则很容易做成「未登录就整页登录引导」，反而丢掉匿名用户能看的内容。

角色色落位：每日推荐 / 推荐歌单 / 排行榜 = 策展（橙）；推荐歌手 = 策展（橙，因为它是服务端策展的）；新碟上架 = 策展（橙）。若后续引入「我的」内容再改用黄。

### 本轮落地结论

- **落点**：
  - `www/mobile/core/ui.js`（新）—— 界面零件层：区块外壳、骨架、空态、错误卡、登录引导、封面卡、曲目行、榜单项、按钮。所有零件自带 `role` + `aria-label`。
  - `www/mobile/core/actions.js`（新）—— 跨视图动作：打开歌单 / 歌手 / 专辑、扫码登录、播放一组曲目。主页与详情页调同一套，避免「同一个动作两种行为」。
  - `www/mobile/views/home.js`（重写）—— 五区块 + 每块独立的状态机。
  - `www/mobile/views/detail.js`（新）—— 歌单 / 歌手 / 专辑三个详情页共用一份实现。
  - `www/mobile/css/shell.css` —— 新增滑轨 / 网格 / 封面卡 / 曲目行 / 错误卡 / 登录引导等样式。
- **五种态是分区块的**：loading（骨架）/ data / empty / error / login。一个区块失败不牵连其他四个。
- **错误按码分支**：`ui.LOGIN_CODES`（`KUMONE_NEED_LOGIN`、`KUMONE_AUTH_EXPIRED`）给「去登录」；`kind === 'transient'` 给「重试」；其余 permanent 不给重试（重试没有意义），只摊开五要素消息与「下一步该干什么」。
- **未登录不是全页状态**：只有拿不到内容的区块才显示登录引导；匿名能拿到的（推荐歌单）照常显示，另外给一条「登录后能看到更多推荐」。
- **落点路径**：歌单 / 歌手 / 专辑统一走 `M.nav({type, id, name})`；`shell.sync` 把这三类视图的底部导航当前项回落成「主页」（`www/mobile/core/shell.js` 的 `rootType` 规则），返回箭头因为有历史而出现。
- **详情页标题可以是函数**：`shell.sync` 支持 `def.title` 是字符串或函数，详情页据此显示歌单名而不是「歌单」。
- **语义契约**：列表用 `<ul><li><button>` 而不是「一个 button 冒充 listitem」—— 之前 `views/library.js` 用 `button[role=listitem]`，快照里那个元素拿不到 ref（`INTERACTIVE` 不含 `listitem`），模型点不了。本轮新写的行一律 `li > button`。
- **自测**：`test/home-view.mjs`（`npm run test:home`）+ 探针 `test/fixtures/probe-home.html`。探针把 `Mobile.service` 换成假服务，四个场景：成功路径、落点路径、错误路径、未登录路径。
- **踩过的坑**：区块内容**没有清掉骨架**就往上叠，结果骨架和数据同时在 DOM 里（探针报「还剩 40 个骨架」才暴露）。修法是回填前先 `body.textContent = ''` —— 「骨架被替换」和「骨架叠在数据下面」在肉眼下很像，但语义完全不同。
- **首屏密度**：每日推荐只摆 10 首（大卡 + 9 首），排行榜只摆 10 条，其余用一行细斜体尾注说明还剩多少。ego 的取向是「块要能一眼扫完」—— 30 首会把后面四个区块推到天边去。推荐歌手与新碟上架是两列网格，各 12 个，密度天然合适。
- **顺带修的**：`shell.setMini` 原先直接 `cover.src = track.cover` 且 `artist.textContent = track.artist`，而归一化后的曲目里艺人是数组、封面可能是 null —— 结果迷你条显示「undefined」、封面请求 `src="null"`。现在两种形态都兜住。

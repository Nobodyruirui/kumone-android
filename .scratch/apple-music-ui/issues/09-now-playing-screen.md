# 09: 全屏播放页

**Blocked by:** 05: 移动端播放引擎, 07: 底部导航与吸顶标题接线

**Status:** done

## 现状与缺口

- 全屏播放页**完全不存在**：`www/mobile/views/` 下只有 `home.js`、`library.js`、`coming.js`；`M.views`（`www/mobile/core/router.js:10`）里没有全屏播放页的视图类型，`www/mobile/core/shell.js` 里也没有它的构建函数。
- 迷你播放条的**数据接口已经备好但无人调用**：`www/mobile/core/shell.js:107-123` 的 `setMini(track)` 与 `:126-131` 的 `setMiniProgress(ratio)` 已能写入封面、歌名、艺人与进度线，但仓库里没有任何调用点。
- **具体缺口**：全屏播放页占满屏幕时**必须隐藏底部导航与迷你播放条**（ADR-0002），而 `shell.js` 的 `boot()`（`:149-165`）无条件构建了 `#m-nav`（`:63`）与 `#m-mini`（`:77`），**没有任何隐藏/显示逻辑**。这正是 ADR-0002 的 Consequences 里点名的「音质、音量这类控制项需要在新落点安放」的前提。
- **具体缺口**：音量与音质在移动端**没有落点**。上游把它们放在常驻完整播放条右侧，而上游的窄屏规则 `www/style-mobile.css:31` 直接 `.pb-right { display: none; }` 把它们整体藏掉了 —— 这就是 spec 说的「手机上不是难用，是根本点不到」。
- **具体缺口**：没有队列视图。播放队列是播放引擎的状态（ticket 05），界面上还没有承载它的入口。
- **具体缺口**：没有空状态。没有当前曲目时全屏播放页会渲染成什么，现在没有定义。
- **具体缺口**：没有降级音质的展示位置。`www/mobile/core/errors.js:24` 的 `KUMONE_UNBLOCK_FAILED` 与 ticket 05 的音质降级都会产生「用户选的和实际生效的不一样」的情况，界面必须能表达这件事。

## 要求

- 新增全屏播放页视图，铺满整个屏幕，进入时隐藏底部导航与迷你播放条，收起时恢复。
- 让全屏播放页展示大封面、歌名、艺人、专辑名。
- 让进度条显示当前位置与总时长，并可拖动跳转；拖动通过播放引擎的命名动词 `seek(t)` 完成，**不直接改 DOM 模拟状态**（ADR-0003）。
- 让上一首 / 播放暂停 / 下一首三个控制可用，并随播放引擎的状态事件实时刷新。
- 让音量可调整，让音质可切换；当所选音质不可用而发生降级时，界面展示**实际生效的音质**。
- 让用户可打开播放队列并看到队列内容。
- 让用户可收起全屏播放页并回到来源页面。
- 让没有当前播放曲目时展示明确的空状态，而不是空白页。
- 让全屏播放页的控件用语义标签 + `aria-label`（播放 / 暂停 / 上一首 / 下一首 / 进度 / 音量 / 音质 / 队列 / 收起），让模型侧能通过快照定位这些控件。
- 让该页面的可交互元素数量与布局在模型快照中可辨认：每个控制一个有名字的 ref。

## 明确不做什么

- 不实现上滑出队列、下滑收起播放页、左右滑切歌、滑动返回等手势（spec 的 Deferred 条目）。
- 不实现逐字歌词页（spec 的 Deferred 条目），尽管 `www/mobile/features/lyrics/apple-lyrics.js` 已在仓库里备好。
- 不在播放页直接操作 `audio` 元素或内核接口，一律经播放引擎（ticket 05）。
- 不在全屏播放页保留底部导航与迷你播放条，即使还有上一屏的内容可返回。

## Comments

这一屏是 ADR-0002 的直接兑现。上游把音质与音量放在常驻播放条右侧，而 `www/style-mobile.css:31` 在窄屏下把 `.pb-right` 整个 `display: none` —— 所以移动端**必须**给这两项重新安排落点，否则就是功能丢失。落点就是本 ticket 的全屏播放页。

三个实现要点：

1. **隐藏逻辑要在外壳层做，不在视图层做。** `shell.js` 的 `boot()`（`:149-165`）无条件建了 `#m-nav` 与 `#m-mini`，隐藏/恢复应当由 `sync()` 或一个专门的外壳方法统一处理，与视图无关 —— 这样任何视图都能要求「隐藏外壳」。
2. **拖动进度条必须走 `seek()`。** ADR-0003 明确「不允许通过直接改 DOM 来模拟状态变化」。直接写 `audio.currentTime` 会让引擎的状态与界面对不上，`player.state()` 就会撒谎。
3. **降级要看得见。** 用户选了 320k 但实际只放得动 128k，如果界面还显示 320k，用户会觉得播放器在骗人。这是错误契约在 UI 层的一个可见落点。

播放队列的**数据**来自 ticket 05 的播放引擎，界面只是它的一个视图。

### 本轮落地结论

- **落点**：
  - `www/mobile/views/nowplaying.js`（新）—— 全屏播放页 + 播放队列视图。
  - `www/mobile/core/shell.js` —— 迷你条的封面/歌名区改成按钮「打开播放页」；新增 `setFullscreen()`。
  - `www/mobile/core/snapshot.js` —— 可交互角色表补 `slider`（进度与音量是 range input，不补就没有 ref）。
  - `www/mobile/core/player.js` —— `state()` 补 `volume`（音量滑杆要读它）。
  - `www/mobile/css/shell.css` —— 播放页与滑杆样式；`body.m-np` 藏导航、迷你条与顶栏。
- **隐藏逻辑在外壳层**：`shell.sync()` 看到 `view.type === 'nowplaying'` 就 `setFullscreen(true)`（切 `body.m-np`）。视图自己不碰外壳 —— 任何视图将来都能要求「藏起外壳」。
- **拖动走 seek()**：滑杆的 `input` 事件调 `player.seek(v)`；`pointerdown`~`pointerup` 之间不回写滑杆值（`dragging` 标志），避免界面和用户抢控制权。
- **降级看得见**：音质按钮显示**实际生效**的音质；用户选的和实际放的不一致时，下面另起一行斜体说明「你选了「极高」，实际放的是「标准」」。
- **状态是活的**：界面订阅 `player.subscribe()`，播放/切歌/音量/音质一变就重画，不需要用户切回来；离开视图时 `leave()` 退订。
- **自测**：`test/nowplaying-view.mjs`（`npm run test:nowplaying`）+ 探针 `test/fixtures/probe-nowplaying.html`。假播放器的音质模型刻意做了降级，好让「降级看得见」那条测得到。
- **踩过的坑**：
  - **首帧被静默跳过**：首屏 `paint()` 是在 `render()` 里同步调的，那时片段还没挂进 DOM，`body.isConnected` 还是 false，于是界面永远停在空状态。修法是改用「视图是否存活」的标志（`alive`），而不是 `isConnected` —— `isConnected` 适合判断**异步回填**，不适合判断**首次绘制**。这条与 ticket 08 的「骨架被替换」是同一个根因的两面。
  - **控件名与快照名不一致**：按钮写的是 `aria-label="收起播放页"`、文字是「收起」，快照里的无障碍名取 aria-label，于是模型按「收起」找不到。语义名应该统一成短名。

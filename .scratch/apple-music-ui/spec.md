## 1. 现状与缺口

### 1.1 视觉：ego 基线已就位，剩下的是收口

- 设计令牌在 `www/mobile/css/tokens.css:37-95`，取值是 ego 风格：白底画布 `--canvas: #f4f4f6`（`:46`）、卡片面 `--surface: #ffffff`（`:47`）、常规描边 `--line: #e3e3e7`（`:42`）、强描边 `--line-strong: #0a0a0a`（`:43`）、文字三档（`:39-41`）、五个角色色（`:54-58`）、卡片圆角 16px（`:70`）、粗体主字 800/700 与 300 斜体副标（`:61-66`）。
- 外壳四构件在 `www/mobile/css/shell.css`：吸顶栏 `#m-header`（`:56`）、内容大标题 `.m-display`（`:110`）、区块标题与细斜体副标 `.m-section-note`（`:129-135`）、底部导航 `#m-nav`（`:139`，当前项用重墨 `--ink` + 700 字重，`:173-174`，不引入颜色）、迷你播放条 `#m-mini`（`:179`，白卡面 + 1px `var(--line-strong)` 黑描边 + `--radius-card`，`:190-193`）。
- 品牌红 `#fa2d48` 在移动端样式中已彻底移除（仅 `www/mobile/reference/legacy-desktop-theme.css:21` 作为对照件保留）。
- **缺口一**：`.m-card` 本体已补上（`shell.css:299-305`：白面 + 1px 描边 + `--radius-card` + `--shadow-card`），但**语义契约的自动检查只覆盖 `button`** —— `test/guard-design.mjs:100-108` 的正则只匹配 `createElement('button')` / `el('button')`；`link`、`tab` 等可交互元素的 `aria-label` 缺失不会被拦下。
- **缺口二**：**裸 CSS 选择器仍然存在**，且没有被任何闸门拦住：`www/mobile/core/shell.js:94` 的 `document.querySelectorAll('#m-nav .m-tab')` 与 `:127` 的 `document.querySelector('#m-mini-line > i')`。它们属于「实现内部面」，按 ego 规则应允许但需显式登记 —— 目前既没有登记机制，也没有把「模型定位面」与「实现内部面」划开（见 `docs/adr/0003` §2）。
- **缺口三**：`www/index.html:8` 的 `theme-color` 已同步为 `#f4f4f6`，与画布一致 —— 这一项**无缺口**，保留在要求里作为不可回退的约束。

### 1.2 内容：四屏仍是骨架，没有真实数据

- 主页 `www/mobile/views/home.js` 是纯骨架：`:44-52` 渲染三个区块（每日推荐 / 为你推荐 / 排行榜），每个区块的内容都是 `skeletonGrid` 占位（`:27-36`）。
- **缺口一**：**区块数量与顺序不对**。要求的是五块（每日推荐大卡 → 横向推荐歌单 → 排行榜 → 推荐歌手 → 新碟上架），当前只有三块，缺「推荐歌手」与「新碟上架」，第二块标题还写着「为你推荐」而非「推荐歌单」。
- **缺口二**：**没有加载占位与错误态的区分**。`skeletonGrid` 是**永久**占位 —— 它不知道数据是「还没来」还是「失败了」，因此网络失败时用户看到的是**永远转圈的骨架**而不是明确的错误提示。
- 资料库 `www/mobile/views/library.js` 的五个入口（`:7-13`）全是死的：`:43` 的点击只弹一句 `M.shell.toast(e.label + ' 将在后续版本开放')`，不请求任何数据。
- **缺口三**：没有二级列表视图。`M.views`（`www/mobile/core/router.js:10`）里没有歌单详情 / 歌曲列表 / 云盘列表这类视图类型。
- **缺口四**：没有账号区。`www/mobile/core/shell.js:49` 已预留 `#m-header-right` 容器，但**没有任何东西往里写**；`www/kumone/lib/api.js:38` 的 `logout()` 也没有移动端侧的消费方。
- 全屏播放页**完全不存在**：`www/mobile/views/` 下只有 `home.js` / `library.js` / `coming.js`；迷你播放条的数据接口 `setMini(track)`（`www/mobile/core/shell.js:107-123`）与 `setMiniProgress(ratio)`（`:126-131`）**在仓库里没有调用点**。
- **缺口五**（**已于本轮收口**）：服务层与播放引擎已落地 —— `www/mobile/core/service.js`（唯一边界：只走内核门面 + 错误按码翻译 + 登录中断）、`www/mobile/core/player.js`（队列 / 下一首 / 四种播放模式 / 音质降级 / 音源解锁兜底 / MediaSession / 持久化）、`www/shared/normalize.js`（共享归一化纯函数，浏览器 + Node 双载），并各有 Node 自测。**仍缺**扫码登录视图（ticket 06）。
- **缺口六**：`www/mobile/core/shell.js:149-165` 的 `boot()` 无条件构建了 `#m-nav`（`:63`）与 `#m-mini`（`:77`），**没有隐藏逻辑** —— 全屏播放页进入时底部导航与迷你播放条不会消失（ADR-0002 的前提未兑现）。

### 1.3 双模态：感知层与动作层已就位，缺的是稳定定位与接线

- `www/mobile/core/snapshot.js` 已实现：ref 分配与复用（`refFor`，`:28-36`）、ref 解析与过期判定（`resolve`，`:39-53`，报 `KUMONE_STALE_REF`）、语义抽取与折叠（`extract`，`:131-169`，`:128-129` 的红线是「任何非空文本都不被删改」）、动作白名单 `click` / `scroll` / `focus` / `fill`（`ACTIONS`，`:221-229`）、动作执行（`act`，`:235-261`，白名单外报 `KUMONE_UNSUPPORTED`）。
- **只读已经是真的**：`refFor` 用 `WeakMap`（`:21`）保存 element → ref，**不往 DOM 写任何东西**（`:26` 的注释明确写了这一点）；快照根从 `#m-app` 改成 `document.body`（`:195`），否则模型看不到挂在 body 上的底部导航与迷你播放条；`live` 映射在每次快照时清理已卸载节点（`:211`）。已有只读回归测试 `test/snapshot-readonly.mjs`，动作层回归测试 `test/model-actions.mjs`。
- **缺口一**：**核心层没有 locator API**。role + name 的匹配实现放在知识包 `www/mobile/learnings/netease/tools/locator.js`（`parseTree` `:104-140`、`findMatches` `:200-213`、`candidateNames` `:216-226`），也就是说**稳定定位只在「加载了知识包」时可用**，`Mobile.snapshot()` / `Mobile.act()` 本身仍只认 ref。ADR-0003 §2 规定的「快照 ref > 语义 locator > 裸 CSS」三层优先级，模型侧目前只能用到第一层。
- **缺口二**：**视图重建导致 ref 断裂**。`www/mobile/core/router.js:52-58` 的 `M.render()` 每次都 `root.textContent = ''` 再重建 `#m-view`，因此同一语义元素在切换视图后是**新的 DOM 节点**、新的 ref。`resolve()` 能正确报 `KUMONE_STALE_REF`（`snapshot.js:39-53`），但这只是把「静默失败」变成「明确报错」，没有提供任何稳定的重新定位手段。
- **缺口三**：**语义标签覆盖不全**。`www/mobile/views/home.js:20` 的区块用了 `role="region"` + `aria-label`（正确示范），但 `home.js:44-52` 的区块内容全是占位；`www/mobile/views/library.js:37` 把 `role="listitem"` 压在 `<button>` 上，快照里该节点的角色**与实际可交互性不符**（`snapshot.js:69-73` 的 `roleOf()` 显式 `role` 优先，会输出 `listitem` 而不是 `button`）。
- **缺口四**：**核心层没有按码分支的证明**。`snapshot.js` 与 `errors.js` 都按码分支，但仓库里没有任何断言能证明**调用方**看的是 `err.code` 而不是 `err.message`。

### 1.4 错误契约：码表已写好，但没接线、且正在漂移

- `www/mobile/core/errors.js` 已实现契约骨架：**14 个码**的码表 `CODES`、契约错误构造 `make()`、五要素消息拼装 `compose()`（缺省部分不出现以免制造噪音）、内核错误映射 `fromKernel()`、可重试判定 `retryable()`。分类按「下一步该干什么」而非按成因：`transient` 四个（网络 / 超时 / 解码失败 / 限流），`permanent` 十个（需要登录 / 登录过期 / 空结果 / 不存在 / 业务拒绝 / 解锁失败 / 引用过期 / 目标不唯一 / 无可操作播放 / 功能未实现）。本轮新增 `KUMONE_BUSINESS_REJECTED`（permanent）。
- **缺口一**（**已于本轮收口**）：**这套契约已有调用方**。`www/mobile/core/service.js` 的 `call()` 是唯一翻译点，把内核失败统一交给 `fromKernel()`；`KUMONE_NEED_LOGIN` 的错误对象额外带 `loginInterrupt: true` 与 `resume: { channel, args }`（扫码成功后原样重放被打断的请求）。视图层仍待接线（ticket 08/10）。
- **缺口二**（**已于本轮收口**）：**`business` kind 已覆盖**。`fromKernel()` 新增 `kind === 'business'` 分支，产出 `KUMONE_BUSINESS_REJECTED`（permanent），`next` 明说「不要重试：换一个请求参数或换一个数据入口」；不再兜底成 `KUMONE_NETWORK`（transient）导致无限重试。
- **缺口三**：**错误码表现在有三份**（权威表 `www/mobile/core/errors.js`；知识包 `www/mobile/learnings/netease/tools/locator.js` 自持一份 5 码子集 `TITLES`；`www/mobile/learnings/netease/manifest.json` 又用 `errorCodes` 写了第三份 5 码说明）。**仍没有任何校验器把三者对齐**，码表漂移是已经发生的事实而不是风险。
- **缺口四**：**五要素没有强制校验**。`compose()` 缺省部分不出现，因此一条只带 `next` 的错误是合法的；「缺省」与「缺失」无法区分，无法判断一条消息是否合格。
- **缺口五**：**码表没有回归保护**。`test/guard-design.mjs` 只检查**每个码都声明了 `kind`**，不检查码的数量、集合、语义，也不检查与知识包副本是否一致。
- **缺口六**：`KUMONE_AMBIGUOUS_TARGET` 有产出点（`www/mobile/learnings/netease/tools/playlist.js`），但它在知识包侧自持的码表里，核心层 `errors.js` 侧没有对应产出路径。

### 1.5 构建期纪律与知识分层：闸门已落地四条，缺口收窄到三类

- `test/guard-design.mjs` 已实现四条闸：体积闸（`LIMITS`，`:39-43`：CSS 48KB / JS 80KB / 字体 128KB）、临时 ref 禁令（`:64-76`）、错误码 `kind` 完整性（`:78-93`）、aria 语义契约（`:95-109`）。
- `test/validate-learnings.mjs` 已实现知识包校验：manifest 可解析、工具模块**真的 require 并调用**（`checkExports` `:87-107`、`smokeCall` `:109`）、禁临时引用（`:57-70`）。
- 浏览器侧回归测试齐备：`test/snapshot-readonly.mjs`（只读）、`test/model-actions.mjs`（动作层与错误契约）、`test/learnings-browser.mjs`（知识包接进应用后可用）。`package.json` 已有 `test:smoke` / `test:guard` / `test:readonly` / `test:model` / `test:learnings` / `test:learnings:browser` 六个入口。
- **缺口一**：**没有「禁裸 CSS 选择器」**。`guard-design.mjs` 的四条闸里没有这一条，所以 `shell.js:94` / `:127` 那种写法不会被拦；而「模型定位面」与「实现内部面」的边界也还没有划出来（ADR-0003 §2 的要求只写了「禁止裸 CSS 选择器」，没写边界）。
- **缺口二**：**没有「禁界面层直接改状态」**。ADR-0003 §10 点名的三类违规里，「裸 CSS 选择器」与「临时 ref」已落地两条，**「界面层直接改状态」这一条没有对应闸门**。
- **缺口三**：**没有「禁按文案分支」**。ADR-0003 §6 要求按码分支，但 `test/` 下没有任何检查会因 `err.message.includes(...)` 式的分支而失败。
- **缺口四**：**体积闸量的不是上下文预算**。`guard-design.mjs:39-43` 量的是 `www/mobile` 目录的**字节数**，而 ADR-0003 §7 说的是「上下文预算」—— 即模型侧一次要读进去的**文本量**（快照树 + 知识包 + 文档）。两者不是一回事，前者是安装包体积，后者是 token 预算。
- **缺口五**：**知识包条目没有失效标记与替代路径**。`www/mobile/learnings/netease/notes/*.md` 里没有失效字段，`test/validate-learnings.mjs` 也不检查它；页面或接口改版导致某条 locator 失效时，仓库里没有地方能标记它。
- **缺口六**：**「schema → 实现 → 回归测试 → 文档」四处同步没有检查**。码表已经有三份（见 1.4 缺口三）就是这项缺失的直接后果。

## 2. 要求

### 2.1 分层与边界

- **R01** 把内核层（`www/kumone/lib/{crypto,client,api,unblock}.js`）保持零改动，除修 bug。
- **R02** 把上游原版渲染层（`www/app.js`、`www/style.css`、`www/style-mobile.css`）保持原样保留在仓库中、不参与加载，作为对照与回退基准；移动端不引用它的 `state` / `player` / `audio`。
- **R03** 把所有移动端改动集中在 `www/mobile/` 一个目录内，不散落到上游文件各处。
- **R04** 让移动端渲染层只通过内核门面 `window.kumone.invoke(channel, args)` 调用网易云能力，保留其统一的成功/失败返回包与「需要登录」语义。
- **R05** 把共享归一化层（曲目 / 歌单 / 专辑 / 歌手 + 播放权判定）提到上游与移动端**共用**的单一位置，两侧引用同一份，不保留副本。
- **R06** 让移动端渲染层自带导航栈与播放引擎，不加载上游渲染层脚本，避免因找不到元素而中断。

### 2.2 视觉语言（ego 风格）

- **R07** 把设计令牌集中保持在 `www/mobile/css/tokens.css` 一处；视图层不得出现硬编码的颜色、字号与圆角。
- **R08** 让界面呈现白底画布、1px 描边、大圆角卡片、克制单色系、粗体主字配细斜体副标；**停止使用品牌红** `#fa2d48`，导航选中态与强调一律用重墨与黑描边表达。
- **R09** 让「颜色即角色」成立：策展=橙 `#f2c489`、我的=黄 `#f5dea9`、自动=蓝 `#a9cbe8`、工具=粉 `#f3c3c0`、中性=灰 `#dcdcdc`；一个颜色只承载一种含义；新增区块必须先确定其角色色。
- **R10** 让字体保持打包进安装包的 Inter 可变字重拉丁子集（含斜体变体），中文回退到系统字体，声明顺序拉丁优先，字体不依赖网络。
- **R11** 保持 `www/index.html:8` 的 `theme-color` 与 ego 画布一致（`#f4f4f6`），不可回退。

### 2.3 外壳与导航

- **R12** 让应用启动后立刻进入移动端外壳（底部导航 + 吸顶标题 + 迷你播放条），而不是被压窄的桌面版侧边栏。
- **R13** 让底部导航四项（主页 / 广播 / 资料库 / 搜索）可切换，选中态跟随当前视图并用 `aria-current="page"` 标记；点击当前项回到顶部而不是重复入栈。
- **R14** 让每一页顶部显示该页名称，切换视图时同步更新标题文本与 `aria-label`。
- **R15** 让页面内容向下滚动时顶部大标题收缩为居中小标题，回顶后恢复。
- **R16** 让底部导航在未实现的广播与搜索上显示占位页，保证四项都有落点、不出现死链接。
- **R17** 让导航栈语义与上游一致：进入下一视图入栈、返回出栈、栈空时回到主页；返回按钮只在有历史时可见。

### 2.4 迷你播放条与全屏播放页

- **R18** 让迷你播放条常驻底部导航之上，显示当前曲目的封面、歌名与艺人。
- **R19** 让用户可在迷你播放条上直接暂停或继续播放，不必先进入全屏播放页。
- **R20** 让点击迷你播放条进入全屏播放页，该页占满整个屏幕并隐藏底部导航与迷你播放条。
- **R21** 让全屏播放页展示大封面、歌名、艺人与专辑名。
- **R22** 让全屏播放页展示播放进度条（当前位置与总时长）并可拖动跳转；拖动通过播放引擎的命名动词 `seek(t)` 完成，不直接改 DOM 模拟状态。
- **R23** 让全屏播放页提供上一首、播放/暂停、下一首三个控制，并随播放状态实时刷新。
- **R24** 让用户可在全屏播放页调整音量。
- **R25** 让用户可在全屏播放页切换音质（不再去找一个在手机上已被隐藏的下拉框）；所选音质不可用时展示**降级后的实际音质**。
- **R26** 让用户可从全屏播放页打开播放队列并看清接下来会播什么。
- **R27** 让用户可从全屏播放页收起并回到之前的页面。
- **R28** 让没有当前播放曲目时展示明确空状态，而不是空白页。

### 2.5 主页

- **R29** 让主页按顺序呈现五个区块：每日推荐大卡 → 横向推荐歌单 → 排行榜 → 推荐歌手 → 新碟上架。
- **R30** 让每个区块在数据返回前显示加载占位，而不是一片空白。
- **R31** 让任一区块请求失败时只在该区块显示错误提示与重试入口，不影响其他区块渲染；错误按 `code` / `kind` 分支（transient 给重试、permanent 给换策略），消息含五要素而不是一句「加载失败」。
- **R32** 让未登录时每日推荐与推荐歌单区块显示登录引导，点击可拉起扫码；排行榜 / 推荐歌手 / 新碟仍正常显示（未登录是**局部**状态，不是整页状态）。
- **R33** 让推荐歌单卡可左右横向滑动，并支持点进歌单详情。
- **R34** 让用户可从排行榜进入某个榜单、从推荐歌手卡进入歌手详情。

### 2.6 资料库与账号

- **R35** 让资料库以分段入口式呈现：播放列表 / 喜欢的音乐 / 云盘 / 最近播放 / 听歌排行。
- **R36** 让用户可从资料库进入某个歌单并播放它。
- **R37** 让用户可在资料库看到喜欢的音乐并直接播放。
- **R38** 让用户可在资料库看到云盘里的歌曲并播放。
- **R39** 让资料库右上角显示自己的头像与昵称。
- **R40** 让用户可点击资料库里的账号区退出登录；退出后清除本地登录态并回到未登录态。
- **R41** 让未登录时点击资料库直接拉起扫码登录，而不是把用户丢到一个空页面；各入口在未登录状态下显示登录引导而非空列表。

### 2.7 扫码登录

- **R42** 让用户可用网易云音乐 App 扫描二维码完成登录。
- **R43** 让二维码过期时可点一下刷新重新获取。
- **R44** 让用户在登录过程中看到当前状态（正在获取二维码 / 等待扫码 / 登录成功 / 已过期）。
- **R45** 让登录过期时收到提示并能重新扫码，登录成功后恢复被打断的操作并回到原本所在的页面。

### 2.8 模型可读界面（双模态）

- **R46** 让同一份 DOM 承担两种角色：人读像素、模型读语义；为模型提供独立的读取接口 `Mobile.snapshot()` 与 `Mobile.act(ref, action, args)`，不要求人去解析像素。
- **R47** 让 `Mobile.snapshot()` 返回当前界面的语义文本树（带缩进的纯文本，不是 JSON），节点带 ref，并以 `[view "..." | refs live]` 作为上下文头。
- **R48** 让同一元素在同一视图内重复快照时 ref 保持不变（已由 `WeakMap` + `test/snapshot-readonly.mjs` 保证）；并让视图重建后语义上同一个元素能通过**稳定 locator** 重新解析到等价目标，不要求模型记住旧 ref。
- **R49** 让快照的降噪遵守红线：可折叠结构（无名空容器删除、单子节点容器用子节点替换自身），但**永远不许删改非空页面文本**。
- **R50** 让可交互元素一律用语义标签（`button` / `nav` / `main` / `h1` / `li`）并带 `aria-label`；**无障碍树就是界面契约**，定位靠 role + name，坐标是最后手段；禁止裸 CSS 选择器与硬编码坐标作为模型定位手段。
- **R51** 让 `Mobile.act()` 的动作严格受白名单约束（`click` / `scroll` / `focus` / `fill`）；白名单外的动作必须返回 `KUMONE_UNSUPPORTED` 并列出可用动作，不得静默忽略。
- **R52** 保持观察只读：`snapshot()` 不改变播放状态、不发请求、不改焦点、**不写 DOM**（`refFor` 不得写 `data-mref` 之类的标记属性）；维持 `test/snapshot-readonly.mjs` 为回归闸。
- **R53** 让状态可查询、转移可命名：播放状态由 `player.state()` 查询，转移由 `play` / `pause` / `seek` / `next` / `prev` / `queue` / `setQuality` 等命名动词表达，不允许直接改 DOM 来模拟状态变化。

### 2.9 错误契约

- **R54** 让错误码表 `KUMONE_*`（14 个，权威源 `www/mobile/core/errors.js` 的 `CODES`）成为持久契约：**按码分支，不按文案分支**；文案可漂移，码不可改语义；新增码必须同步码表、自测与文档三处。
- **R55** 让错误按「下一步该干什么」分类为 `transient`（可原地重试）与 `permanent`（须换策略）；等待循环只对 transient 重试。
- **R56** 让错误消息遵循五要素：期望签名、当前状态、候选、阻塞原因、下一步动作；并让「该类错误必备哪些要素」成为可校验的规则。
- **R57** 让所有内核失败经 `fromKernel()` 统一翻译成契约错误，界面层不得自造错误结构；补齐 `business` kind 的映射并归入 permanent。
- **R58** 让错误码表**只有一份**：知识包 `www/mobile/learnings/netease/tools/locator.js:35-41` 的 `TITLES` 与 `www/mobile/learnings/netease/manifest.json:39-43` 的 `errorCodes` 必须由校验器与 `www/mobile/core/errors.js:15-29` **逐码对齐**，不允许各持一份。

### 2.10 知识分层与构建期纪律

- **R59** 把网易云页面的稳定定位器沉淀为知识包 `www/mobile/learnings/`，**只允许稳定 locator，禁止临时 ref**；长尾细节通过查询获取，不写进常驻文档。
- **R60** 让知识包中的每条知识是可执行的制品（能被程序加载并校验其可调用性），而不是散文；条目带失效标记与替代路径。
- **R61** 让上下文预算成为构建期纪律：把**模型侧一次要读入的文本量**（快照树 + 知识包 + 文档）的上限写进自测，超限即失败；`test/guard-design.mjs` 现有的目录字节体积闸（`:39-43`）是安装包体积，不是上下文预算，两者都要有。
- **R62** 让约束前移成构建错误：裸 CSS 选择器、临时 ref、界面层直接改状态、按文案分支，在自测里失败，而不是靠代码评审发现；并把「模型定位面」与「实现内部面」划清边界（实现内部面允许，但需显式登记）。
- **R63** 让「schema → 实现 → 回归测试 → 文档」四处同步成为可检查项，任一处缺改即失败。

### 2.11 工程流程与可验证性

- **R64** 让学习者能随时在浏览器里打开网页版看界面（`npm run web` → `http://localhost:8100`），不必每次都打 APK。
- **R65** 让每次提交都能跑一遍既有内核自测（`npm test` 期望 ALL MATCH、`npm run test:live` 期望 6/6 endpoints OK），确认没把加密与请求链路弄坏。
- **R66** 让移动端的纯逻辑（数据归一化、播放状态机、错误契约、快照与动作）有可重复执行的自动化验证，并接入 npm script。
- **R67** 让测试只断言外部行为（给定内核门面的输入输出，界面层应产生什么可见结果），不对 DOM 结构的具体写法做脆弱断言；视觉与交互用真机人工验收清单覆盖。

## 3. 明确不做什么

### 3.1 红线条（本轮不做，且不接受「顺手做掉」）

- **不改内核层**：`www/kumone/lib/{crypto,client,api,unblock}.js` 除非修 bug，否则一行不动。
- **不重构上游原版渲染层**：`www/app.js` 及其样式保持原样，不接受顺手优化。
- **不引入前端框架、组件库、构建步骤或打包器**：沿用现有 `www/` + Capacitor 的直出结构。
- **不重做桌面宽屏布局**：本项目只做手机端。
- **不新增商店类 tab**：网易云没有对位数据。
- **不把品牌红带回来**：ego 风格里品牌红不再使用。
- **不让移动端渲染层与上游渲染层同时加载**。
- **不让模型通过裸 CSS 选择器或硬编码坐标定位界面元素**。

### 3.2 Deferred（未落地，明确记录）

> Deferred 条目必须写清三件事：**为什么不做** / **不做会怎样** / **什么时候做**。这让「没做」与「忘了做」在仓库里可区分。

**D1 · 逐字歌词**

- **为什么不做**：代码已在 `www/mobile/features/lyrics/apple-lyrics.js` 且可用，但需要适配移动端的歌词容器类名，且依赖播放引擎与歌词加载的挂钩方式；本轮播放引擎（ticket 05）已落地，但全屏播放页（ticket 09）还没有歌词区容器，挂钩点仍不存在。
- **不做会怎样**：全屏播放页没有歌词区，用户看不到词级高亮；播放页少一个预期中的信息层，但不影响「能播歌」的主闭环。
- **什么时候做**：ticket 09 的全屏播放页落地后（播放引擎已就位），作为下一个 feature 单独开票；接入时必须补回上游被绕过的那条「需要登录」语义翻译。

**D2 · 手势（上滑出队列、下滑收起播放页、左右滑切歌、滑动返回）**

- **为什么不做**：手势与「点击」不是同一类交互，模型侧的动作白名单（`click` / `scroll` / `focus` / `fill`）无法表达它们；要支持就得把「模型可读界面」扩成一套触摸协议，复杂度与本轮目标不匹配。
- **不做会怎样**：收起播放页、打开队列、切歌都改用显式按钮完成，功能不缺但少了一分顺手；模型驱动场景完全不受影响（它本来就用 `act` 而非手势）。
- **什么时候做**：在模型侧动作白名单之外单开一张票设计触摸协议时；设计时必须同时回答「模型要不要能驱动手势」。

**D3 · 广播与搜索的实装**（✅ 已于 ticket 15 实现）

- **当初为什么不做**：广播是持续流式播放，依赖播放引擎的长队列与续播语义；搜索需要分页与结果详情页，两者都超出本轮四屏的范围。
- **不做会怎样**：底部导航四项里有两项是占位页，点进去看到「将在后续版本开放」；不影响主页、播放页、资料库、登录的完整闭环。
- **什么时候做**：播放引擎稳定运行、且主页与资料库的数据形态定型之后，作为独立 feature 排期。
- **实际落地**：在主页 / 资料库 / 播放页都稳定之后按用户要求做掉（ticket 15）。两屏的取舍：
  - 广播不做「续播」（播完自动要下一首），只做「下一首」按钮 —— 续播要长队列与插播语义，属于播放引擎的扩展。
  - 搜索不做分页与「加载更多」，只做首屏 30 条 —— 与主页同一原则。
  - 为让模型也能驱动搜索，动作白名单加了 `fill`（这是本轮唯一的契约变更）。

**D4 · 深色主题与跟随系统明暗**

- **为什么不做**：ego 视觉语言以白底画布为基线（`docs/adr/0003` 视觉语言表），加一套深色意味着每个角色色都要重新推导一版明度，纯色系与「颜色即角色」的约束在暗色下会松动。
- **不做会怎样**：深色系统下应用仍是浅色界面；这是**有意为之**（ego 风格是工程化、克制的选择），不影响任何功能。
- **什么时候做**：只有在角色色体系能承载两套明度时才做；届时必须重走角色色推导，而不是把浅色值机械反转。

**D5 · 自动化 UI 测试与截图对比测试**

- **为什么不做**：真机环境（Android 设备或云端设备）不可控，截图对比的基线会因字体回退、系统版本、WebView 版本而抖动，产出大量噪声；而 ego 的可靠性能策略是**把约束前移到语义与契约层**（role + name 定位、错误码契约），不是像素层。已有的浏览器回归测试（`test/snapshot-readonly.mjs` 等）走的正是语义与契约路线。
- **不做会怎样**：视觉与交互靠人工验收清单（ticket 11）覆盖，回归靠 Node 自测覆盖纯逻辑；版式类回归需要人看一次。这是本轮明确接受的代价。
- **什么时候做**：当 CI 能稳定提供同版本同设备的截图环境时；优先级低于语义层契约测试。

**D6 · 上游原版渲染层的重构**

- **为什么不做**：ADR-0001 已决定不就地改造上游；就地重写会让 diff 淹没在上游代码里、无法分辨哪些是本项目改动，且上游随时可能更新，独立目录便于 rebase。
- **不做会怎样**：上游原版界面保持桌面取向的旧观感，窄屏下仍有七个控件点不到（`www/style-mobile.css:31`）；这不影响移动端渲染层，二者并存不同时运行。
- **什么时候做**：不计划。若上游更新导致对照基准失效，只做最小适配以维持可对照性。

**D7 · 桌面宽屏布局的重新设计**

- **为什么不做**：本项目只面向手机；上游原版渲染层承担宽屏形态。
- **不做会怎样**：宽屏下用上游界面，移动端渲染层只保证手机尺寸下的正确性。
- **什么时候做**：不计划。

**D8 · 引入前端框架、组件库、构建步骤或打包器**

- **为什么不做**：移动端渲染层目前的规模（四个 core 模块 + 三个视图 + 一个知识包）远未到需要框架的量级；引入框架会与「只有 `www/` 被打进 APK」「入口页面直接加载脚本」的现有链路冲突。
- **不做会怎样**：视图代码保持手写 DOM 构造，组件复用靠约定而非框架；视图数量增长后这部分会变痛。
- **什么时候做**：当视图数量与交互复杂度增长到手动维护明显吃力时；届时先评估「自建极小组件层」而非直接引框架。

**D9 · 发布链路的首次演练（推 `v*` 标签 → GitHub Actions → 公开 Release）**

- **为什么不做**：`.github/workflows/build-android.yml` 已配置就绪（`v*` 标签触发 Release），但需要**已验收的界面**才有意义 —— 在真机验收（ticket 11）之前出包等于把未验收版本发出去。
- **不做会怎样**：拿不到可下载的安装包，真机验收（ticket 11）无法完成；**这是 ticket 11 的前置阻塞项**。
- **什么时候做**：ticket 11 的验收清单逐条勾选通过之后，由具备仓库推送权限的人打第一个 `v*` 标签。

### 4.2 模型操作序列（`Mobile.snapshot()` / `Mobile.act()`）

- [ ] **M1 读树**：`Mobile.snapshot()` 返回 `{ ok: true, scope: 'full', tree }`，tree 首行是 `[view "home" | refs live]`，后续是带 role 与 name 的缩进节点。
- [ ] **M2 ref 稳定**：连续两次 `Mobile.snapshot()`，同一元素的 ref 相同（两次都出现 `button "资料库" [ref=@12]`）。
- [ ] **M3 动作白名单**：`Mobile.act("@12", "click")` 返回 `{ ok: true, action: 'click', ref: '@12', role: 'button', name: '资料库' }`，且界面发生对应变化。
- [ ] **M4 stale ref**：切走视图使元素被卸载，再执行 `Mobile.act("@12", "click")` → `ok: false`、`code === 'KUMONE_STALE_REF'`、`kind === 'permanent'`，且 message 的 `Next` 段给出「重新取一次快照」。
- [ ] **M5 非白名单动作**：`Mobile.act("@12", "swipe")` → `ok: false`、`code === 'KUMONE_UNSUPPORTED'`，message 的 `Blocked by` 段列出 `click / scroll / focus / fill`。
- [ ] **M6 稳定 locator**：用 role + name 的稳定 locator 定位「资料库」导航项并点击，无需记住上一次的 ref 也能命中同一元素。
- [ ] **M7 只读观察**：`Mobile.snapshot()` 前后各读一次播放状态 → 两次读数完全一致；调用期间 Network 面板无新增请求；`document.activeElement` 未改变；**DOM 未被写入**（不产生 `data-mref` 之类的标记属性）。
- [ ] **M8 按码分支**：构造一个 `permanent` 错误进入等待循环 → **立即抛出**而不是继续轮询；构造一个 `transient` 错误 → 允许重试一次。
- [ ] **M9 语义可读**：在模型快照里读到「播放列表」「喜欢的音乐」「云盘」「最近播放」「听歌排行」「播放」「暂停」「上一首」「下一首」「队列」「收起」等语义名与各自的 ref。
- [ ] **M10 非空文本不被删改**：对同一页面对比模型快照与实际可见文本，确认快照里的非空文本与页面一致，没有被降噪规则删改。

# 第三轮：歌词修复 / 我的歌单 / 收藏专辑 / 播放模式 / 上传仓库

Status: ready-for-agent
Feature: phone-fixes-3

## Problem Statement

1. **大部分歌没有歌词** —— 实测根因不是「有些歌没歌词」，而是我们的取法错了。
2. **没有「加入歌单」「收藏专辑」**，用户想整理自己的内容时无处可去。
3. **没有播放模式开关** —— 引擎里四种模式早就写好了，界面却没有出口。
4. 需要把这几轮的成果**推到 GitHub**，且**不能带个人信息**。

## Solution

1. **歌词**：网易云返回的 `lrc` / `tlyric` 是**对象** `{version, lyric}`，我们当字符串用 → `String(obj)` 变成 `"[object Object]"` → 解析出 0 行 → 显示「暂无歌词」。逐字歌词那层取的是 `.lyric` 字段，所以**只有带逐字的歌能显示**。修法：服务层统一取出字符串。
2. **我的内容**：服务层补齐建歌单 / 加歌单 / 收藏专辑 / 收藏列表四个能力；界面用**底部抽屉**承载「加入歌单」，不切页面、不丢上下文。
3. **播放模式**：播放页加一个循环切换按钮（顺序 → 单曲循环 → 列表循环 → 随机），直接写进引擎既有的 `setRepeat`。
4. **上传**：先做个人信息体检（邮箱、昵称、本机绝对路径、构建产物），再提交推送。

## User Stories

1. 作为听众，我想**大部分歌都能看到歌词**。
2. 作为听众，我想歌词里的「作词 / 作曲 / 填词」这类信息行**不要混进正文**。
3. 作为听众，我想在播放页**一键把当前这首歌加进我的歌单**。
4. 作为听众，我想在浏览歌单时**逐首加入自己的歌单**。
5. 作为听众，我想**新建歌单**（资料库里能建，加入歌单时也能建）。
6. 作为听众，我想**收藏专辑**，并在资料库里找到收藏的专辑。
7. 作为听众，我想在专辑页看到**当前是不是已收藏**。
8. 作为听众，我想切换**顺序播放 / 单曲循环 / 列表循环 / 随机**。
9. 作为听众，我想这些面板的打开与收起**顺滑不跳**。
10. 作为开发者，我想把这轮成果**推到 GitHub**，且仓库里**不含个人信息**。

## Implementation Decisions

- **歌词取文本**集中在服务层的一个小函数里，兼容「对象」与「字符串」两种形状。
- **加入歌单用底部抽屉**（新的界面零件）：从下方滑入、点背景收起；抽屉里列出现有歌单，底部直接输入名字新建并加入。
- **曲目行的「+」与主按钮平级**（不能嵌套在 button 里），带语义名，模型能点。
- **收藏专辑放在专辑详情页**，初始状态靠读「收藏的专辑」列表判断（不猜）；资料库新增「收藏的专辑」入口。
- **播放模式按钮在播放页辅助区**，四种模式循环，标签用文字（顺序 / 单曲循环 / 列表循环 / 随机），不用图标。
- **一级菜单不动**：底部仍是主页 / 广播 / 资料库 / 搜索；新能力挂在资料库、详情页与播放页。
- **上传前做个人信息体检**：扫邮箱、昵称、本机绝对路径、构建产物与本地配置。

## Testing Decisions

- 沿用既有 seam：服务层 Node 单测 + Edge headless 探针 + guard 闸。
- 新增探针覆盖：播放页两个新按钮、模式循环顺序、抽屉能选能建、详情每行「+」、资料库新入口、专辑收藏切换。
- 歌词修复有服务层断言（对象形状 → 字符串）+ 解析断言（元信息行被跳过）。

## Out of Scope

- 不做歌单排序 / 批量移动 / 删除歌单。
- 不做收藏歌手、收藏歌单。
- 不做歌词下载与离线缓存。
- 不做推荐算法相关的「每日歌单」。

## Further Notes

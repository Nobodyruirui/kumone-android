# 01: 歌词真的出得来 + 我的内容齐活

**What to build:** 用户刷到任何一首歌都能看到它的歌词；能把自己的歌单建起来、把歌加进去、把专辑收藏起来；播放页能切顺序 / 单曲循环。

**Blocked by:** None (can start immediately)

**Status:** ready-for-agent

- [ ] 整行歌词的歌也能显示（接口给的是 `{version, lyric}` 对象，取 `.lyric`）
- [ ] 「作词 / 作曲 / 填词」这类元信息行不进正文
- [ ] 播放页有「加入歌单」与「播放模式」按钮
- [ ] 播放模式循环：顺序 → 单曲循环 → 列表循环 → 随机，并写进引擎
- [ ] 「加入歌单」用底部抽屉：能选歌单、能直接新建并加入
- [ ] 歌单 / 专辑 / 歌手详情的每一行有「+」按钮
- [ ] 资料库有「收藏的专辑」入口；我的歌单页有「新建歌单」
- [ ] 专辑页有「收藏」按钮，能收藏也能取消
- [ ] 服务层单测 + 视图探针全绿

## Comments

已完成（2026-10-31）。
**歌词**：取证 `.scratch/probe-lyric-shape.js` —— 接口的 `lrc` / `tlyric` 是**对象** `{version, lyric}`，我们当字符串用 → `String(obj)` = `"[object Object]"` → 0 行 → 「暂无歌词」；逐字那层取的是 `.lyric` 所以只有带逐字的歌能显示。修法：服务层统一取字符串；并把「作词/作曲/**填词**」等元信息行从正文过滤（实测整行歌词开头常是它们）。
**我的内容**：服务层补 createPlaylist / addToPlaylist / subscribeAlbum / likedAlbums；界面用**底部抽屉**承载「加入歌单」（新零件 `ui.sheet`），不切页面；曲目行的「+」与主按钮**平级**（不能嵌套在 button 里），带语义名。
**信息架构**：底部四个一级菜单**不动**；加入歌单挂播放页 + 详情每行；新建歌单挂资料库「播放列表」页 + 抽屉里；收藏专辑挂专辑页，收藏完在资料库「收藏的专辑」找。
**播放模式**：引擎的四种模式（`off/all/one/shuffle`）本来就写好了，这轮只是把出口接到播放页，循环顺序 顺序 → 单曲循环 → 列表循环 → 随机。
证据：`npm run test:service` 新增 16 条断言全绿；新增探针 `npm run test:mine:view`（19 条断言）全绿；全量 22 项自测全绿。
真机项：验收清单 3.37–3.45。

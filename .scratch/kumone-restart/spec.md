# Kumone Android 开工工作流程

## 这一轮交付什么

在现有 Kumone Android 上完成一个能日常试用的版本。用户打开 App 后，可以搜索一首有播放权限的歌，点播后从迷你播放条展开全屏播放页，操作进度和队列，再收起播放器继续浏览。需要账号时，通过扫码登录回到发起操作的位置。手机锁屏后依然可以控制播放。

首轮演示选「搜索 → 播放 → 展开与收起 → 回到搜索结果」。这条路径覆盖现有外壳、真实播放状态和 ego 语义契约，也最容易看出 Apple Music 的播放体验是否融入了 Kumone。

## 开发基线

- **开发仓库**是本地 `kumone-android`。起点 `3f47bd9`，`main` 比本地记录的 `origin/main` 领先 3 个提交。沿着现有 Capacitor、移动端渲染层、服务层和播放引擎增量开发。原生桥继续负责 Android 平台能力。[项目说明](../../README.md) · [移动端入口](../../www/index.html)
- **导航和账号**采用当前代码与 ADR 的约定。底部为「主页 / 广播 / 搜索 / 收藏」，顶栏左侧「我的」打开抽屉，右侧处理账号。游客能打开「我的」和「收藏」，需要账号的内容提供登录入口。登录只走扫码。「收藏」放收藏的歌单和专辑，「我创建的歌单」归「我的」。`AGENTS.md` 的三键导航、密码登录及部分旧验收记录需要对齐到这套约定。[词汇表](../../CONTEXT.md) · [收藏 ADR](../../docs/adr/0004-收藏升为一级功能.md) · [扫码登录 ADR](../../docs/adr/0005-只保留扫码登录.md)
- **GitHub fork**的 README 显示它是 Enji Music，Android 使用 Bern 生成的 Jetpack Compose 界面。重点对照迷你播放条、歌词与系统媒体控件，以及它让可见控件和命令共用行为的思路。Kumone 继续复用自己的架构和素材。[Enji Music README](https://github.com/Nobodyruirui/vanyiyun/blob/d201839a2851e5a072896a31589f5f4a5317655c/README.md) · [Android 播放截图](https://github.com/Nobodyruirui/vanyiyun/blob/d201839a2851e5a072896a31589f5f4a5317655c/docs/screenshots/android-lyrics.png)

## 设计方向

| 方向 | 落到 Kumone 的决策 |
| --- | --- |
| Apple Music 的播放体验 | 让封面、歌名和艺人构成阅读重点。迷你播放条在浏览时常驻，点击展开全屏播放页。全屏把播放、进度、歌词与队列放在清晰的层级里，收起时回到原来的搜索结果和滚动位置。 |
| Kumone 的 ego 视觉语言 | 用现有令牌统一浅色画布、细描边、大圆角、主次字重与角色色。当前项由字重、描边和语义状态共同表达。保留 Kumone 自己的布局、图标与品牌标识。 |
| 人和模型的操作契约 | 同一套界面提供可读标签和 `Mobile.snapshot()` 的语义树。读快照保持播放和页面状态，动作经 `Mobile.act()` 白名单触发。使用语义角色和名称稳定定位。错误沿用 `KUMONE_*`，同时给出可执行的下一步。 |
| Android 交互 | 在真机上校验状态栏安全区、系统返回、边缘返回、字体放大和媒体通知。浏览器用于快速迭代界面及语义，真机承接音频、扫码、锁屏和 WebView 验收。 |

参考 [Apple 播放控件](https://support.apple.com/en-euro/guide/iphone/iph676daac9b/ios)、[Apple 播放队列](https://support.apple.com/en-euro/guide/iphone/ipha4521ef7d/ios)、[ego-lite 快照](https://github.com/citrolabs/ego-lite/blob/main/package/ego-browser/README.md) 和 [Kumone 双模态 ADR](../../docs/adr/0003-双模态界面与ego视觉语言.md)。

## 把 ego-lite 理念落到开发动作

| 原文中的原则 | Kumone 的做法 | 检查方式 |
| --- | --- | --- |
| 控制权与动作意图（§1） | 登录由用户发起，授权由用户在网易云音乐 App 内完成。登录取消或授权中断时停在可恢复的位置，等待用户再次发起。模型可以读当前登录状态与下一步，凭据留在既有会话流程。 | 从「收藏」进入扫码，分别演示取消后回到来源页、刷新过期二维码、授权成功后在来源页刷新内容。 |
| 感知、语义与 ref（§2） | 用有名称的语义控件表达目标和当前状态。快照保留歌名、艺人、结果状态、错误与有效控件，优先收起重复或空的结构。关注单个区域时复用现有子树快照。 | 在受控测试数据下重复取快照，验证同一控件的 ref 可复用，观察过程未改变播放、焦点、滚动或发起请求。页面变动使旧 ref 失效时，用当前快照重新定位。 |
| 观察 → 决策 → 动作 → 验证（§3） | 可复用脚本按 `role + name` 查找当前 ref，经 `Mobile.act()` 触发同一个可见控件。长期规则保存语义定位器，临时 ref 只用于当前界面。动作后等待曲目、控件名或页面状态更新，再以快照或只读查询确认。 | 用语义入口执行搜索、点播、展开与收起。两个目标同名时先用有名称的区块缩小范围，再确认唯一目标。 |
| 错误指向下一步（§4） | 延用 `KUMONE_*` 的错误码和 `kind`。网络异常提供重试，旧 ref 提示重取快照，歧义提示用更具体的语义目标，登录到期提示用户扫码。每次重试以当前状态或用户明确操作为依据。 | 模拟断网恢复和失效 ref，分别断言重试后的结果、拒绝动作时的稳定错误码及恢复路径。错误详情沿用期望操作、当前状态、候选（如有）、原因、下一步的契约。 |
| 知识分层与构建约束（§5–6） | 在工作流程里留入口与验收路径。较长的契约说明进对应 ADR，稳定定位器进现有知识包，运行细节就近放到测试或实现说明。用仓库已有的守卫检查加载资源体积、语义契约和临时 ref。 | 执行 `test:guard`。知识包改动加跑 `test:learnings`，定位器行为改动加跑 `test:learnings:browser`。公开接口变更同步接口定义、实现、回归和对应文档。 |

截图用于审定封面层级、布局和转场。语义快照用于核对控件、状态与动作目标。只要其中一种证据足以回答当下的问题，就只取这一种。原型评审各留一份代表性画面和语义快照，供两种操作者核对同一路径。

原文依据 ego-lite 的界面设计理论拆解（本机工作区内的独立文档，未入库），仓库内可参照[理论摘要](../../docs/ego-lite-UI设计理论.md)及[双模态 ADR](../../docs/adr/0003-双模态界面与ego视觉语言.md)。

## 用户可验收的行为

1. 作为游客，我能进入搜索、找到一首游客可播的曲目，并在点播后看到迷你播放条更新。
2. 作为正在听歌的人，我能展开全屏播放页，确认当前曲目，暂停、继续、拖动进度和切歌。
3. 作为正在听歌的人，我能打开播放队列查看接下来播什么，并在收起播放器时回到原搜索结果。
4. 作为正在听歌的人，我能在系统通知或锁屏上暂停与继续，回到 App 后能看到同步的状态。
5. 作为游客，我能浏览「收藏」和「我的」的入口，并在需要账号时自行发起扫码。
6. 作为账号用户，二维码过期时我能刷新，登录后回到来源页，能分辨我创建的歌单与收藏的歌单。
7. 作为弱网用户，我能区分加载、空结果、可重试失败与不可播曲目，并能继续浏览或选其他歌。
8. 作为依赖无障碍或语义自动化的用户，我能用清楚的控件名称完成同一条路径，并在 ref 已失效时重新获取快照再操作。

## 执行顺序

以 Matt Pocock 的垂直切片方式推进。每一步都用一段可演示的用户行为收尾，优先处理已经满足依赖的切片。下表是本轮待办，正式实现票沿用仓库的[本地 Markdown 工单约定](../../docs/agents/issue-tracker.md)。

| 步骤 | 前置 | 交付与验收 |
| --- | --- | --- |
| 01 建立基线 | 当前提交 | 用现有脚本验证播放、搜索、全屏播放页和语义契约，记录通过、失败和跳过。同步 Web 资源并构建 Debug APK。设备可用时，先装当前构建，冒烟验证真实出声、后台自然续播与锁屏控制。 |
| 02 做播放路径原型 | 01 的浏览器基线 | 复用现有外壳与模拟数据，先录下当前路径，确定一个实际需要改的层级或交互问题。做一个可点原型，在 390×844 和一个更窄的手机视口评审操作顺序、封面与文字层级、控件名称、回原页状态。用下方双模态检查给出证据。 |
| 03 打通搜索与播放的视觉改版 | 02 | 把原型接到现有搜索与播放入口。让全屏与迷你播放条显示同一首曲目，暂停、拖动进度和队列操作共享播放状态。收起播放器恢复查询、结果和滚动位置。补齐空态、断网和封面失败回退，用既有入口做回归。 |
| 04 验证收藏与扫码回跳 | 01 的浏览器基线，可与 02、03 并行 | 游客打开「收藏」，主动选择登录，扫码成功后回到来源页并刷新数据。覆盖刷新二维码、取消登录、退出与切换账号，并验证旧账号的会话与收藏数据随退出清理。核对「我的」与「收藏」各自展示的内容。 |
| 05 真机验收并打包 | 03、04 及 01 的 Debug APK 构建链 | 安装当前提交构建的 APK。先测真实音频与扫码，再测安全区、系统返回、前后台、锁屏和通知切歌。记录设备、Android 版本、构建提交及复现步骤。成果为可安装的本地测试包和验收记录。 |

每个切片按「可复现缺口 → 预期行为与范围 → 实现 → 回归证据」推进。先记下所用提交、入口、触发步骤、看到的结果和期望结果。行为或接口契约发生变化时，先更新对应规格或 ADR。优先沿用服务层、播放引擎、路由和语义接口，以用户或模型能观察到的结果验收。跳过的项记录原因和补验条件。

### 首个播放切片的双模态检查

前置使用一组固定搜索结果，包含可播放曲目。浏览器原型可用模拟播放，真实出声在 Android 验收。以当前外壳为起点保留同一份演示数据。

| 检查 | 可观察的结果 |
| --- | --- |
| 人操作搜索与播放器 | 输入关键词，点一首歌。迷你播放条显示正确的封面、歌名和艺人。展开全屏后确认同一首歌，暂停后播放状态明示。看队列、收起，再回到原结果与原滚动位置。 |
| 模型操作同一路径 | 以语义快照找到输入框与播放按钮，以当前 ref 调用 `fill` 或 `click`。在点播、展开、暂停、收起后读取相应状态。演示记录能看到曲目、操作状态和返回位置对应的页面。 |
| 重读与恢复 | 对稳定界面取两次快照，比较控件 ref 与可观察状态。再离开页面使该控件失效，旧 ref 返回 `KUMONE_STALE_REF`，取新快照后可继续操作。对活跃 ref 传入未知动作，返回 `KUMONE_UNSUPPORTED`。 |
| 网络与空态 | 断网时界面有可执行的重试，恢复网络并重试后能看到结果。空结果可继续编辑关键词。不可播曲目提示可换一首，封面加载失败时显示占位，播放入口仍可操作。 |

工作票记录演示入口、视口和测试数据，以及有代表性的截图、快照或回归结果。首个原型重点交付搜索、播放和返回的顺序。完整异常覆盖随步骤 03 验收，扫码和锁屏各用自己的切片验证。

## 跑测与交付

首次依赖安装用 `npm ci`。浏览器预览用 `npm run web`，界面回归使用仓库的 Edge/Chrome 探针。探针会使用 8100 端口，跑探针前先停掉仅服务 `www/` 的预览进程，让探针能访问仓库根下的 fixture。

排查顺序从能否启动开始。探针缺少输出时，依次核对 8100 端口实际服务的目录、探针页是否加载、是否产生 PASS/FAIL。Edge headless 未返回结果时，用 ego-browser 打开同一 fixture 复核，分别记录两边结果。`SKIP` 单独记录，并注明缺少的运行条件。

| 检查 | 命令或操作 |
| --- | --- |
| 内核与播放 | `npm test`、`npm run test:smoke`、`npm run test:player`、`npm run test:fm-search` |
| 语义契约 | `npm run test:guard`、`npm run test:readonly`、`npm run test:model`、`npm run test:model-flow` |
| 搜索与播放器 | `npm run test:fm-search:view`、`npm run test:mini:cover`、`npm run test:nowplaying`、`npm run test:back:restore` |
| 收藏与扫码 | `npm run test:login`、`npm run test:login:view`、`npm run test:favorites`、`npm run test:mine:entry` |
| 真实接口与 Android | `npm run test:live` 做匿名接口联通检查，以输出的 `6/6` 为准。真机上用可播曲目验证真实出声、后台切歌和账号流程。浏览器替身测试和真实接口结果各自记录。 |

Windows 打包所需 JDK 21、Android SDK 35 及 SDK 路径见[仓库构建说明](../../README.md)。更新渲染层后先同步资源，再构建：

```powershell
npm run sync
.\android\gradlew.bat -p .\android assembleDebug --console=plain
```

APK 路径为 `android/app/build/outputs/apk/debug/app-debug.apk`。真机按[现有验收清单](../../docs/验收清单.md)记录结果。旧条目 3.1、3.17 中的「资料库自动拉起扫码」按本轮「收藏可直接进入，由用户发起扫码」验收。

播放验收使用网易云原站音源，核对测试配置中第三方音源兜底已关闭。接口返回不可播时，明确反馈并允许选其他曲目。截图、语义快照和日志只记录验收所需信息，省略登录二维码、Cookie 与账号标识。

## 后续范围

等核心路径稳定后，再评估深色主题、下载与离线曲库、桌面歌词、跨平台迁移以及对外发布。广播和逐字歌词按现有行为做回归。项目的第三方音源能力留给独立需求评估。

ego-lite 的 TaskSpace 所有权、跨进程 ref 和运行时 `help()` 属于它的浏览器架构。Kumone 本轮复用已有语义和会话接口，等出现实际的多操作者或跨会话恢复需求，再单独评估这些机制。

对外推送前的登录探针凭据核查已完成（2026-11-21）：`.scratch/probe-login.cjs` 的手机号与密码从命令行参数传入，默认值是假号；`.scratch/` 下其余 email / token 探针里的账号字面量均为占位值（`nobody@163.com`、`13000000000` 等），未发现真实凭据，**无需更换凭据或改写待推历史**。正式发布再核对 Android 版本号与签名，当前构建流程产出 Debug APK。

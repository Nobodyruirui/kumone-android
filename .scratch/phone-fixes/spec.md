# 真机四修：封面 / 歌词 / 账号登录 / 返回手势

Status: ready-for-agent
Feature: phone-fixes

> 现状与缺口都带可核对的证据；口径沿用 `docs/adr/0003-双模态界面与ego视觉语言.md` 与仓库既有术语。

## Problem Statement

用户在真机（Android）上装了这个 App 之后遇到四个问题，四个都直接影响「能不能正常用」：

1. **有些歌曲封面加载不出来。** 歌单封面、专辑封面正常，歌曲封面一片空白或裂图。
2. **没有歌词。** 全屏播放页只有封面和控件，没有歌词。
3. **只能扫码登录。** 用户想用账号（手机号 + 密码）登录，扫码要求另开一个 App，不方便。
4. **返回上一级点不了，也不能左滑返回。** 顶栏的返回箭头被手机状态栏（通知栏）盖住，点不到；也没有左滑返回的手势；页面之间的切换是硬切，没有动画。

## Solution

按「先取证、再修」的方式处理，四项分别对应：

1. **封面统一走 https + 加载失败兜底。** 根因是网易云接口对**歌曲**封面返回 `http://` 图片地址（实测：每日推荐、搜索结果、推荐歌手 100% 是 `http://p1..p4.music.126.net/...`），而**歌单 / 专辑**封面返回 `https://`。App 的页面 origin 是 `https://localhost`（Capacitor `androidScheme: https`），Capacitor 默认 `android.allowMixedContent = false` → 混合内容被 WebView 拦掉。修法：在归一化层把**所有**图片地址统一改写成 https（沿用 `normalizeSongUrl` 已有的同类做法），并给 `<img>` 加加载失败兜底（不再显示裂图）。
2. **全屏播放页加歌词面板。** 逐字（卡拉 OK 扫光）优先，没有逐字时回退整行高亮；当前行自动居中滚动。
3. **登录页改成「账号登录」为主、「扫码登录」为备选 Tab。** 实测网易云 `/login/cellphone`（手机号 + 密码）接口仍存活（假账号返回 `502 账号或密码错误`）；`/login/email`、`/login/password` 已 404 下线 —— 所以账号登录只能是手机号 + 密码。
4. **顶栏不再被状态栏压住，并且能左滑返回。** targetSdk 35 + Android 15 强制 edge-to-edge，而 Capacitor 默认 `adjustMarginsForEdgeToEdge = "disable"`，WebView 直接顶到屏幕顶；而 Android WebView 里 `env(safe-area-inset-top)` 恒为 0，CSS 的安全区留白等于没写 —— 这就是返回箭头被盖住的直接原因。修法：交给 Capacitor 的边到边边距处理；同时在移动端渲染层实现「边缘左滑返回」与「前进 / 返回的转场动画」，并把 Android 硬件返回键接到同一条返回路径上。

## User Stories

1. 作为听众，我想让**歌曲封面**在真机上正常显示，这样我能靠封面认歌。
2. 作为听众，我想在歌单 / 专辑封面上看到**同样的图片质量**，这样界面不会一半好一半坏。
3. 作为听众，当封面地址失效时，我想看到一个**占位块**而不是裂图图标，这样界面不显得坏掉。
4. 作为听众，我想在播放页看到**歌词**，这样我能跟着唱。
5. 作为听众，我想要**逐字卡拉 OK 效果**（当前唱到的词被点亮），这样更有沉浸感。
6. 作为听众，当这首歌**没有逐字歌词**时，我想看到整行歌词并高亮当前行，这样至少能跟。
7. 作为听众，当这首歌**完全没有歌词**时，我想看到明确提示（而不是空白），这样我知道不是加载失败。
8. 作为听众，我想在歌词面板里看到**翻译行**（如果接口有返回），这样我看得懂英文歌。
9. 作为听众，我想让歌词面板**跟随播放进度自动滚动**到当前行，这样我不用手动找。
10. 作为听众，我想在播放页**切回封面**，这样我能在看歌词和看封面之间来回切。
11. 作为用户，我想用**手机号 + 密码**登录，这样我不用再掏另一个 App 扫码。
12. 作为用户，我想在登录页看到**「账号登录 / 扫码登录」两个 Tab**，这样两条路都在，随时能切。
13. 作为用户，我想在密码错误时看到**明确原因**（而不是「登录失败」四个字），这样我知道是密码错还是网络断。
14. 作为用户，我想让**密码不落盘**（不写进 localStorage、不进日志），这样我的凭证只在这一次请求里出现。
15. 作为用户，我想让账号登录成功后**回到我被打断的地方**（比如本来在点资料库），这样流程不断。
16. 作为用户，我想让扫码登录**依然可用**，因为有些场景扫码更方便。
17. 作为用户，我想让顶栏的**返回箭头不被状态栏盖住**，这样我点得到它。
18. 作为用户，我想在有返回历史的页面**从屏幕左边缘右滑**就能返回，这样单手也能用。
19. 作为用户，我想让左滑是**跟手的**（手指走到哪、内容跟到哪），这样我知道松手会发生什么。
20. 作为用户，我想在滑动不足时**弹回原位**，这样误触不会丢掉当前页面。
21. 作为用户，我想让页面之间的切换**有丝滑的转场动画**，这样我不觉得卡。
22. 作为用户，我想让**前进和返回的方向相反**（前进从右进、返回往左出），这样方向感一致。
23. 作为用户，我想让 Android **硬件返回键**和顶栏箭头、左滑走同一条路径，这样行为一致。
24. 作为用户，我想让**没有返回历史时**按返回能正常退出 App，而不是卡住。
25. 作为模型（通过 `Mobile.snapshot()`），我想在歌词面板上读到**当前行与歌词文本**，这样我能理解界面状态。
26. 作为模型，我想在登录页读到**两个 Tab 的当前选中态**，这样我知道用户在哪一步。
27. 作为开发者，我想让所有改动都有**回归测试**，这样以后改内核不会把封面和歌词改坏。
28. 作为开发者，我想让**体积闸**继续拦着界面层别无限膨胀，这样安装包和上下文预算都还受控。

## Implementation Decisions

- **改动集中在一个新的 feature 目录**：spec 与 tickets 放在 `.scratch/phone-fixes/`；实现落在 `www/mobile/`（界面与契约层）、`www/kumone/lib/api.js`（内核，仅两处增量）与 `android/`（Capacitor 配置与返回键）。
- **封面地址归一化放在共享归一化层**（`www/shared/normalize.js`），而不是各视图各写一遍：新增一个「图片地址规整」纯函数，对曲目 / 歌单 / 专辑 / 歌手 / 账号头像统一生效，规则是「空 → 空；`http:` → `https:`；按用途追加尺寸参数」。因为归一化层浏览器与 Node 双载，**Node 单测可以直接断言**。
- **视图层不再各自拼 `<img>`**：界面零件层新增一个统一的封面元素工厂，负责「规整地址 + 加载失败兜底」，视图只传 URL 与替代文本。
- **歌词解析是纯函数模块**：新增「歌词解析」契约层模块，输入接口返回的 `lrc / tlyric / yrc` 三种文本，输出统一的「行」结构（每行有起始时间、时长、文本、词级时间片、可选翻译）。有逐字就带词级时间片，没有就只带行级 —— **解析不碰 DOM、可在 Node 里逐条断言**。
- **内核只做一处增量**：歌词请求加 `yv=-1` 以取回逐字歌词（原本不带就没有 `yrc` 字段）；账号登录新增一个手机号 + 密码的通道，登录成功后把 Cookie 并入内核的 cookie jar。除此之外内核零改动。
- **密码只在这一次请求里出现**：不落 localStorage、不写日志、不进错误消息；失败时只回报「账号或密码错误」这一类结论。
- **登录页是「一个视图、两个 Tab」**，不是两个页面：扫码那套状态机原样保留，只是降为备选 Tab；账号登录是新增的一个提交表单。两者共用同一套「登录成功 → 刷新账号 → 回到被打断处」的收尾。
- **手机号 + 密码失败时自动再试一次另一种密码编码**（明文 / MD5 各试一次），两次都失败才判为「账号或密码错误」；这样不赌网易云服务端当前认哪种编码。
- **状态栏遮挡交给 Capacitor 的边到边边距**：把 `adjustMarginsForEdgeToEdge` 从默认的 `disable` 改成 `auto`（Android 15+ 自动给 WebView 加系统栏边距，低版本系统行为不变）。**不**改成 `force`，避免在旧系统上多出一截空白。
- **返回手势与转场动画在移动端渲染层实现**：导航渲染器负责转场（前进从右进、返回往左出），边缘手势负责「跟手 + 阈值判定 + 弹回」。手势只在**有返回历史**时启用，且让出屏幕最边缘的一条窄带，避免和 Android 系统的返回手势打架。
- **硬件返回键接到同一条路径**：原生侧把返回键转成一次 JS 调用；JS 侧有历史就返回上一页并走同一套动画，没历史才退出 App。
- **不做的事**：不引入新的运行时依赖（逐字歌词、动画、手势全部手写，体积闸口径不变）；不把上游原版渲染层拉回来；不动 `www/kumone/lib/` 里除歌词与登录之外的部分。

## Testing Decisions

- **只测外部行为**：断言「归一化后的地址长什么样」「解析出来的歌词行是什么」「服务层在假门面上返回什么」「视图 DOM 里有没有那个元素」，不测内部实现细节。
- **沿用仓库既有的三层接缝**：
  - **Node 纯函数 / 服务层单测**（先例：`test/normalize.test.mjs`、`test/service.test.mjs`、`test/login.test.mjs`、`test/player.test.mjs`）：新增图片地址规整、歌词解析、账号登录服务层的断言。
  - **Edge headless 探针**（先例：`test/browser.mjs` + `test/fixtures/probe-*.html`，跑在全新 profile 上）：新增「歌词面板渲染」「登录页两个 Tab」「边缘左滑手势触发返回」的探针。
  - **构建期闸门**（先例：`test/guard-design.mjs`）：体积 / 临时 ref / 错误码 / 语义契约四条闸继续全绿，新代码不得越线。
- **内核改动的既有闸门**：改完内核先跑加密基线自测与真实接口连通自测，两者都要全绿。
- **真机项单独记账**：状态栏遮挡、边缘手势、逐字扫光这三项**无法**在桌面浏览器里等价验证，按仓库约定记为「待真机验证」，交付新 APK 后由用户在手机上确认。

## Out of Scope

- 不做网易云的验证码登录（图形验证码 / 短信验证码）：接口在风控时会要求，本轮只把服务端返回的结论如实透出。
- 不做「用 Cookie 导入登录」的第三条路。
- 不做歌词的逐字编辑 / 桌面歌词 / 歌词分享。
- 不改音质降级链、播放队列、云盘、FM 等本轮没提到的功能。
- 不做 iOS / 桌面端适配，不动上游原版渲染层。
- 不做搜索分页、队列「下一首播放」曲目明细等已登记的其它已知问题。

## Further Notes

- **取证脚本**（本轮新增，放在 `.scratch/`，不进包）：`probe-covers.js` 统计各接口封面地址的协议分布；`probe-cover-scheme.js` 定点比对同一张图的 http / https 可达性；`probe-login.js` 探测账号密码登录接口是否还活着。结论已写进上面的 Problem Statement。
- **封面为什么不是「有些歌」而是「所有歌曲」**：协议分布与接口绑定 —— 每日推荐、搜索结果、推荐歌手走的是会返回 `http://` 的那批接口；歌单 / 专辑 / 新碟上架走的是返回 `https://` 的那批。所以用户看到的现象是「歌单封面有、歌曲封面没有」。
- **同一台机器上 `curl` 能取到这些图片、Node 的 `http.request` 却超时**：是本机 Node 的连接路径问题，与 App 无关；判定「地址可用」以 `curl` 实测为准。
- **体积余量**：进包口径当前 CSS 29.3KB / 48KB、界面与契约层 JS 155.9KB / 192KB，本轮新增歌词面板、登录表单与手势大约会吃掉 15–25KB JS 与 5–8KB CSS，仍在闸内。

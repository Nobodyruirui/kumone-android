# 05: 左滑返回与丝滑转场

**What to build:** 用户在**有返回历史**的页面从屏幕左边缘向右滑，内容**跟着手指走**；滑够了就返回上一页，滑不够就弹回原位；页面之间的切换有方向一致的转场动画（前进从右进、返回往左出）；Android 硬件返回键与顶栏箭头走同一条路径。

**Blocked by:** None (can start immediately)

**Status:** ready-for-agent

- [ ] 边缘手势只在有返回历史时启用，滑动手感跟手（跟到手指位置）
- [ ] 滑动超过阈值才返回，不足则弹回原位（误触不丢页面）
- [ ] 转场动画方向一致：前进从右进、返回往左出，动画不卡顿
- [ ] 顶栏返回箭头点击与左滑结果一致
- [ ] Android 硬件返回键：有历史就返回上一页，没历史才退出 App
- [ ] 手势让开屏幕最边缘的一条窄带，不与系统返回手势打架
- [ ] 视图探针断言：合成触摸事件能触发返回

## Comments

已完成（2026-10-31）。转场做在路由层：旧内容搬进「上一层」容器再各自动画 —— 前进时新页面从右边进、旧页往左淡出；返回时旧页往右出去、上一页从左边进来（方向与前进相反）。
手势做在新的手势模块：从左边缘 46px 内起手才启用，内容**跟手**移动；滑过 26% 屏宽（或速度够快）才返回，不够就弹回原位；全屏播放页不启用（它有自己的「收起」）；横向歌单区与滑杆不抢手势。
硬件返回键：Activity 的返回键转成一次 JS 调用，界面层有历史就返回上一页（走同一套动画），没有就调新插件退出 App —— 顶栏箭头、左滑、硬件键三条路同一条。
证据：`npm run test:back:view`（Edge headless，合成触摸事件）9 条断言全绿。
真机项：手势跟手感与动画流畅度（验收清单 3.27 / 3.28 / 3.29）。
